# Sites backend handoff: publication and assets

Task 1 implements the managed-site publication boundary on this worktree. It does **not** make a site available on the public internet. Task 2 must replace the explicit denying public gate only after it has real host ownership, provider routing, TLS and current-readiness checks.

## Shared contract

`@school/shared/site-manifests` exports `SITE_MANIFESTS_V1`, `siteManifest(key, version)`, `validateSiteContent`, `canonicalSiteFieldValue`, `canonicalSiteContent`, `SiteContentV1`, `SiteManifestV1`, `PreviewSiteV1`, `PublicAssetV1` and `PublicSiteV1`. The sole registered key is `school-core-synthetic-v1` at schema version `1`. Its routes are `home` at `/`, `about` at `/about`, and `contact` at `/contact`. Fields are required `school_name` (text, 120 chars, identity evidence), required `intro` (text, 1,000 chars) and optional `hero_image` (hero asset reference). This is an explicitly selected synthetic renderer descriptor, not a default or an OBHIS registration. `rich_text` has no registered parser and is denied; reviewed external links have no registered destination resolver and are denied. Unknown keys, versions, fields, routes, duplicates, markup, controls, CSS/script-like text and extra object keys are rejected. Only the code-owned primary/accent tenant theme seam can supply branding later; content does not accept CSS or extra brand colours.

The revision envelope remains `fields: [{fieldId, value}], routeSeo: [{routeId, title?, description?, shareAssetId?}]`. Field evidence is keyed `v1:<rendererKey>:<schemaVersion>:<fieldId>:<hex SHA-256 of canonical typed value>`. Revision `contentDigest` is a hex SHA-256 of canonical sorted validated content. Asset evidence is keyed `v1:<assetId>:<Convex storage SHA-256>`; The registered checksum and asset subject use lowercase hex. The storage metadata may report hex or base64; admission decodes and compares either representation to the canonical digest. Never compute the asset key from a client checksum. A new manifest needs an exact compiled renderer counterpart, not an implicit fallback.

`PublicSiteV1.applicationLink` is the real `ApplicationLinkV1` from `@school/shared`: `href`, `availability`, `schoolSlug`, `intakeSlug`, `opensAt`, `closesAt` and version `1`. No site function invents an admissions URL. Task 2/3 must resolve that DTO with server time and the existing configured-origin resolver; `/s/{schoolSlug}` and optional `/i/{intakeSlug}` belong to foundation. Portal remains unavailable without an approved destination.

POST `/sites/asset-upload` is an authenticated Convex HTTP action. Headers: `Content-Length` 12 to 5,000,000 measured bytes, `Content-Type` exactly `image/png` or `image/jpeg`, `X-Site-School` with the school ID, `X-Site-Kind` from `logo|favicon|hero|gallery|staff|facility|social_share`, `X-Site-Filename`, `X-Site-Alt`, optional `X-Site-Decorative: true`. Body is raw image bytes. A bounded pixel decoder validates the input, and a pure-JavaScript PNG encoder removes ancillary metadata before storage. JPEG is transcoded to PNG; WebP is rejected until a safe supported decoder exists. The byte count and hex checksum describe the stored PNG, not the original upload. It stores first, then registers through the internal mutation with propagated authentication. It deletes the newly stored object if registration fails. Success is 201 JSON `{assetId}`. Missing identity or rejected registration returns 403; invalid headers/body return 400, excess size 413 and unsupported image bytes 415. Denial does not return a storage ID or URL. No CORS grant is installed: a future browser UI must use a reviewed same-origin server proxy or a deployment-owned origin allowlist, not wildcard CORS. Upload is not a replacement for the admissions document workflow. No PDF/active document type is accepted yet.

POST `/sites/asset-bytes` is deliberately registered as a constant 404 with `Cache-Control: no-store`. Task 2 must replace it with an actual host/current-publication/rights gate before returning any byte. It must never redirect or reveal a signed `_storage` URL. Any first-party Sites byte route should call the fresh gate for each request. Reuse `validatePublication` and `approvedAsset` in `functions/sites/shared.ts` with the publication's publisher ID; the helper checks independent reviewers and current storage/evidence/expiry. Check that the asset is marked published and referenced in the **current** publication, not merely approved in the same school. A host supplied by a caller without trusted ingress checks is not authority.

## Evidence policy and operational limits

The synthetic `school_name` must match the active school's persisted name at approval and at publication. Identity values also require a current same-school `identity` evidence record from a separate `privacy.approve` reviewer. Sensitive public fields require `sensitive_public`; every image also requires separately approved rights and child applicability. `contains_children` additionally requires child-consent evidence. `unknown` and missing classification deny. Revocation, expiry, checksum substitution and any change to a fact's typed value deny at the next admission check. The publisher may not be the approver for either fact or image evidence. A platform admin may provision the profile but is not a school fact approver.

The source/reference is a bounded reviewer-supplied record description, not an automatically authenticated external document. Human reviewers must actually inspect the independently held school source before approving. This code cannot attest that a written reference corresponds to a real document; do not treat a `confirmed` flag or the reviewer grant as proof of a real school's identity or image rights. No real school facts or child photos were approved here. A verified immutable evidence-source integration would be needed before claiming automated source verification. Synthetic tests use fictional references only.

The installed `convex` package is **1.34.1**. Its `defineApp()` does not provide the guideline's newer typed `env` declaration option. Task 1 adds no provider env values. Task 2 should read its required provider config through one server-only, strict validation helper using the installed API, reject missing/placeholder settings in production and document its keys. Do not upgrade Convex just to use `defineApp({env})`. Neither platform-provided Convex URL belongs in an app env declaration.
