# D2 — OBHIS public website information architecture and visual direction

**Stage:** Design | **Role:** Designer | **Depends on:** G2 | **Worktree:** documentation/design only

## Objective
Turn the OBHIS brief into a bespoke, school-first website direction—not a reskin of the current template—while preserving an externally stable admissions-link contract.

## Scope
- Approved sitemap, nav, mobile nav, page goals, CTAs, and funnel map for Home, About, Academics/Programmes, Admissions, Facilities/Gallery, Contact/Visit, and optional policy pages.
- Low/high-fidelity page directions with desktop/mobile behavior, visual tokens, typography, content hierarchy, and photography treatment.
- Source-of-truth matrix: booklet-derived content, content needing school approval, and content that must not be inferred.
- A media shot list, logo/brand requirements, consent/rights requirements for child images, alt-text strategy, SEO metadata brief, and performance budget.
- Link behavior for managed-domain and external-domain contexts, including application and portal CTAs.

## Constraints
- No unconfirmed fee, contact, programme, facility, statutory, or outcome claim.
- No platform branding in the public school experience unless expressly approved.
- Renderer layout remains code-controlled; editable content must conform to G2’s typed model.

## Deliverables
- `docs/features/OBHISWebsiteDesignSpecification.md`
- `docs/mockups/sites/obhis-public-site.html` (or design-file/export reference)
- `docs/features/OBHISContentApprovalSheet.md`

## Done when
- B5 can implement the bespoke site without deciding facts or visual direction.
- The admissions CTA points to the G1 canonical contract, never a hard-coded tenant-only form.
- All visual/content blockers are explicitly owned by OBHIS or the delivery team.
