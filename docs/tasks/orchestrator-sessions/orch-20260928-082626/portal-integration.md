# B3 portal integration

The portal now resolves the authorized student's class for each session and term before building any graded card. Narrative mode returns a separate issued snapshot or a neutral not-ready state. An ambiguous unissued historical enrollment returns a neutral review state with no class, scores or comments. Other failed enrollment checks return no report. Neither path falls back to live grades. The workspace history uses a narrative variant without score fields. Dashboard, results, notifications and the report page consume that same guarded workspace response. Parent print renders only the selected issued snapshot, with its original subject names, order and class. The direct narrative portal queries now omit the issuing staff member and draft metadata.

Admin review prints one student's issued report or a clearly marked unpublished draft on A4. Both staff report routes require a class before loading graded data. The teacher report route sends narrative classes to subject entry instead of graded preview or batch print. The admin launcher now opens an issued-only narrative class batch at `printClass=1`. A school-admin-only Convex query checks class, session, term and mode, reads the new class/session/term issued index, and returns snapshots without drafts or staff metadata. It counts unissued students against a bounded roster. More than 40 students or issued reports fails closed rather than printing an incomplete class. The print page shows the number skipped; the graded stack is unchanged. The R3 follow-up also includes graduation records when counting unissued pupils from an inactive class session. It rejects the entire batch if the UTF-8 serialized response exceeds 512 KiB, even when each issued snapshot is individually valid. The error tells staff to print smaller batches or individual reports. Legacy staff links without `classId` use verified period evidence before choosing a report mode; links with no evidence ask for a class. Normal selector-generated links are unchanged. Narrative print CSS forces all text to dark ink on white paper, including the portal's inline tenant-coloured heading. Sections allow long comments to continue across A4 pages; headings stay with following text. `node scripts/narrative-print-smoke.mjs` rendered the portal's print CSS in Chromium: the inline pale heading computed to rgb(17, 24, 39), and a 160-line comment produced three A4 PDF pages. A two-student admin batch with a long first report produced four A4 pages and hid the controls. The admin batch markup/CSS also has a targeted test for issued snapshots, skipped count and break rules. Browser smoke does not cover an authenticated app session or every printer's pagination.
