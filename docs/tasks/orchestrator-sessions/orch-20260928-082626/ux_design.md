# FR-023 narrative report UX

**V1 scope update, 2026-09-28:** The user clarified that each assigned subject needs its own comment, entered through the normal teacher session, term, class, subject and student flow, in place of scores. Admin chooses comment-vs-score mode for selected classes per session. School-admin subject assignment stays the normal source; editable Melo starter subject sets/templates may be offered as optional convenience. The previous single-comment and mandatory rubric/card/template ideas below are superseded. FR-023 is authoritative; use the normal selector layout and a clean per-subject report. Draft/publish and parent issued-only safeguards remain.

This spec is the UI handoff for FR-023. Keep existing graded routes and their visual language. The decision record in `design-contract.md` owns the data and publication rules. A class's reporting choice is scoped to school, session and term, never to class level or enrollment. A new class-term is graded until an admin explicitly selects narrative. No narrative selection means no narrative setup for the school. Do not promise families access when a teacher saves a draft.

## Admin setup flow

At the top show "Reporting modes", then session and term selectors with current values always visible. Below them, a two-column desktop layout places "Class sets" on the left and the selected set's details on the right. On phones stack selectors, set list and editor in that order. Each set card shows its name, class count, mode and template name when narrative; an expandable per-class list shows each effective mode, including unselected classes as "Graded (default)". Filter active classes by name, then check one or more arbitrary same-school classes. Show selected count and removable class chips. Levels are labels for orientation, not filters that decide eligibility. Save requires a nonempty set name, at least one eligible class and, for narrative, a selected template version. Use explicit "Save choices for this term" rather than "Apply to school". For a conflict, keep selections and show "This class is already in another set for this term. Remove it there before saving." Link to that set if known. Server rejection for archived, foreign or mismatched class/term should retain the form and identify the affected choice without leaking another school's details.

The template editor sits beside the set editor or opens from its "Create template" control. Ask for a template name, then ordered learning-area cards. Each card has a stable key shown as a read-only identifier once saved, editable display label, "Observation required" checkbox, and optional descriptive scale choices with stable keys and editable labels. Move controls reorder cards without changing keys. Example labels can be "Communication" and "Working with others"; avoid numbers, grade bands or proficiency points. Show a sample report using the current labels. Save creates a new version when changing a saved template; label the version in the assignment and explain "Published reports keep their original wording." Do not repurpose extras' numeric, boolean or mutable scale fields. Show length and count limits beside fields once the backend sets their bounds; client hints supplement server validation.

Before changing a class-term's mode, show a confirmation dialog naming session, term and affected classes: "Switch reporting mode for these classes? Unpublished work in the previous mode stays saved for staff but will not appear as the active report. Families cannot see narrative drafts. This does not change enrollment or previously published reports." Buttons: "Keep current mode" and "Switch mode". When any affected class-term has an issued report, disable switching and say "Mode locked: a report has already been published for this class and term. Choose a different term." No silent partial bulk success. A new term or class is not prechecked because a prior term used narrative. If no templates exist, show "Create a narrative template before assigning narrative reporting" with the editor action; graded selection stays usable.

## Teacher draft flow

`WorkbenchHeader` retains the Session, Term, Class and Student order. A small context label below it says "Narrative report · Draft" or "Narrative report · Published". Render each learning area in template order as a labeled card: optional descriptive choice in a labeled select or radio group, then a multiline "Observation" input. End with "Overall teacher comment"; admin-only "Head-teacher comment" follows in the staff review/editor. The scale is descriptive only and never substitutes for a required observation. "Save draft" saves incomplete work; a saved confirmation says "Draft saved. Families cannot see this report until an admin publishes it." Show unsaved changes before switching student/context, including when using next-student navigation. Save failure preserves text and offers retry. Required blanks and invalid choice keys do not block saving an incomplete draft, but mark review as incomplete: inline "Add an observation for [area] before publishing" and a summary linked to each offending input. A missing overall teacher comment is likewise identified if publication requires it. The admin preview must reflect the latest saved draft, not unsaved text. An assigned teacher can edit their class's draft; unrelated staff and parents cannot open it. After issue, fields are read-only, with "Published on [date]. This report cannot be edited." Teachers do not see a publish action.

Before selection, show "Choose a class and student to write a report." While loading, use stable skeletons for selectors and area cards; avoid flashing graded scores. An enrolled class with no students says "No enrolled students in this class for this session and term." A narrative class with no subjects still displays the full observation editor. If the mode query fails, show a retry state, not a fallback graded form.

## Admin review and publish

The left navigator still selects one student. Above the right preview show the student, historical class, session, term, mode and template version. The preview must match the narrative print order and text exactly. A separate review panel lists missing required observations or invalid descriptive choices, and includes the optional head-teacher comment before preview refresh. Until all checks pass, "Publish report" is disabled with a written reason. Once ready, admin explicitly reviews the current preview and confirms "Publish [student]'s narrative report for [term]? Families linked to this student can then view and print this fixed copy. You cannot edit it afterward." The confirmation is per student, not a bulk publish. On success show "Published [date/time]" and actor, and switch preview to the issued copy with print enabled. A repeated click should show the existing issued copy, not a second publication.

If draft, template, theme, extras or other publishable presentation changes after preview, stop publication with "This report changed since you reviewed it. Refresh the preview and review again." Preserve selected student and return focus to "Refresh preview". A server rejection or connectivity failure must not imply success. If another kind was issued for this student/period or the class-term became locked, show the issued record/status and block the incompatible action. Unpublished narratives are always labeled "Staff draft. Not visible to families" on review and staff print.

## Parent view and paper

The portal `ReportCardsView` in `PortalWorkspaceContent.tsx` already offers child and history selection. For an issued narrative, show "Progress report", school branding, student name and admission number, class at issuance, session and term, then learning-area headings in template order with observation paragraphs and optional scale labels, overall teacher comment, optional head-teacher comment and issue date. Offer print next to the title. Long text wraps; no score table, grade, average, rank, cumulative warning, pending subject count or numeric history badge. On `/results`, use "Progress report available" and a link to the issued report for this term, not a synthetic subject result. Dashboard uses a narrative report link instead of a numeric term snapshot. Notifications may announce the issued narrative, never drafts or pending scores.

For an unissued narrative term show "Report not ready" and "The school has not published this term's progress report yet." No observation, template label, comment, scale choice, score fallback, pending-score alert or print action. A historical issued card stays available after promotion or a later term's mode change, with its original class and wording. Child/session/term changes refresh the entire selection; never retain the previous child's report while loading. If no issued history exists, show the same neutral availability message rather than a score placeholder. These states assume the portal query supplies only authorized issued narrative snapshots. Do not change the separate agent's graded-parent visibility policy here.

Use a dedicated narrative renderer adjacent to `packages/shared/src/components/ReportCardSheet.tsx`, dispatched by report kind, rather than feeding narrative data into its numeric `results` contract. Its A4 sheet uses white paper, a clear school heading and student context, a single-column learning-area list, readable body type of roughly 11 to 12 pt in print, 12 to 16 mm margins and page breaks between, not through, area cards where possible. Repeat context on later pages if a long report spills; never shrink paragraphs until illegible. Keep monochrome borders and text meaningful if brand fills do not print. Parent printing consumes the issued snapshot only. Batch staff print uses the right renderer per student and preserves current graded print behavior, including graded-only cumulative blocking; narrative pages have no cumulative warning.

## Visual and interaction rules

Keep existing app type, neutral backgrounds, rounded cards and compact context selectors. On mobile, use one column, full-width labeled fields and actions, no horizontal score table or zoom-dependent editor. Keep a visible save action after the final field and enough bottom padding for phone controls. Desktop may pair navigator and preview as the existing admin page does. Do not rely on color alone for Draft, Needs review, Published and Locked; use text labels and plain status icons. Tenant branding accepts only `primaryColor` and `accentColor`, derived through `@school/shared/theme`; text on branded fills uses matching `--school-*-contrast` tokens. Product-neutral surfaces remain neutral, status/error colors remain semantic, and grade-policy colors remain reserved for graded output. Print uses white paper and dark text even when a tenant has a bright theme.

All controls have visible labels, keyboard focus rings and at least 44 px touch targets where practical. Class cards and term history are buttons with announced selected state. A bulk class list uses actual checkboxes, not clickable text alone. The switch confirmation traps focus and returns it to the initiating control. After save/publish, announce the status in a polite live region; validation errors use an error summary with links to fields and `aria-describedby` on inputs. Keep focus on the first invalid field after attempted review. Do not use animation as the only state cue; respect reduced motion. Body text and controls target WCAG AA contrast, including derived tenant fills and monochrome print.

## Reviewer checklist

- [ ] Admin can name and inspect same-school term-scoped sets across any class level; no action enrolls a child, makes a subject or provisions a parent.
- [ ] Default graded and existing graded workbench, certification, preview and print remain usable; no narrative controls appear merely because a class is foundation.
- [ ] Mode change warns about dormant staff drafts, refuses an issued class-term and never silently affects another term.
- [ ] Teacher/admin drafts support no-subject classes, required observation errors and optional descriptive labels; only admin can review and publish one student at a time.
- [ ] Stale review, invalid choices and failed publish show clear recovery; issued copy is fixed and read-only.
- [ ] Parent selected card, dashboard, results, history, notifications and print show only issued narrative content; unissued narrative shows neutral not-ready with no numeric fallback.
- [ ] Historical class, versioned area labels and paper output stay correct after promotion, template edits or later mode changes.
- [ ] Narrative screen and A4 print omit numeric marks, grades, averages, rankings and cumulative/pending-score text; draft staff print identifies itself.
- [ ] Mobile, keyboard, error focus, contrast and monochrome print pass review with both bright and dark tenant colors.

There is no design blocker for v1. Backend bounds on template size and text length should be surfaced as helper text once fixed. The other agent owns any global change to existing graded-parent visibility; integration must test both policies without weakening the narrative issued-only rule.
