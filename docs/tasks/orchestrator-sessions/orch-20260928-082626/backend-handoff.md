# B1 backend handoff

FR-023 now uses one draft per student, class, session, term and subject. No single-comment contract remains. `classSessionReportModes` still defaults to graded when no row exists; a narrative choice applies to the whole class session and cannot change after either kind of issuance. Mode selection neither enrolls students nor creates subjects.

The functions live in `api.functions.academic.narrativeReports`. `listClassModes({sessionId})` returns `{classId, mode, locked}` for active classes. Admin `setClassModes({sessionId, classIds, mode})` accepts 1 to 50 distinct same-school classes. `getClassMode({classId, sessionId})` remains the report-preview-authorized staff mode, including class assignment checks for teachers. Exam-entry navigation must instead call `getEntryClassMode({schoolId?, classId, sessionId})`. It checks the authenticated branch's `academic.assessments.enter` permission and same-school class/session and returns `{mode: "graded" | "narrative", canEnterNarrative: boolean}`. The Boolean is true only in narrative mode when the actor also passes the actual report-preview capability check and is a school admin or an assigned teacher for that class; an archived class yields false. A permission-managed exam officer without report-preview permission gets the mode but `canEnterNarrative: false`. B2 should show a static access message instead of calling `getSubjectOptions` or `getSheet` when mode is narrative and this flag is false. The flag is a navigation hint, not write authorization. Permission-managed exam officers and teachers whose old same-school class selection is no longer assigned can still read the mode. Parents, other schools and unauthenticated callers cannot. This query never reads students or drafts and does not authorize a score sheet or narrative save; those endpoints keep their separate subject/class checks. Never infer a mode from school level.

For subject entry, call `getDraft({studentId, classId, sessionId, termId, subjectId})` and `saveDraft({...selection, subjectId, comment})`. Draft text may be empty and has a 10,000-character limit per subject. Server checks tenant, student enrollment in the session class, term, effective selected subject and teacher class-subject assignment through `assertTeacherAssignment`. Admin can edit any applicable subject. A form teacher can edit any offered subject under the existing assignment helper. Unrelated teachers and parents cannot read drafts. Explicit student session selections replace the class offering fallback. Archived subjects in an offering or explicit selection are excluded from current entry and preview, matching `getSubjectOptions`; if none remain, publication rejects with `Assign subjects before publishing`. Previously issued snapshots keep their archived subjects and original names. Narrative entry deliberately uses selectable component subjects rather than computed grading-aggregation umbrellas. `getSheet`, `getDraft`, `saveDraft` and publish use the same per-component policy; an umbrella cannot become an unenterable required comment. This differs from graded reports' derived-umbrella and opt-out calculation. Subjects are sorted by name then ID for stable review. A full unissued report preview is admin-only so a teacher assigned to one subject cannot read another teacher's drafts. Once issued, a class-authorized teacher may read that immutable copy.

Admin `getStaffPreview({studentId, classId, sessionId, termId})` returns `{status, snapshot, reviewedKey, issuedAt}`. The draft snapshot has a `subjects` array of `{subjectId, name, order, comment}`. Mark draft previews "Draft, not published". `publish({...selection, reviewedKey})` refuses zero applicable subjects, blank comments, a stale review, or an issued graded report. Preview and publish reject a JSON-encoded snapshot above 256 KiB, well below the 1 MiB Convex document limit and leaving space for the preview's duplicate review key. Shorten comments before retrying. Repeated publication returns the original immutable record. For `getStaffPreview` and individual issued print, an exact issued row is accepted as historical enrollment evidence when a pupil moved classes and the old session is inactive without a promotion/graduation row. The server verifies the issued row's school, class, student, session and term after staff class authorization; `getStaffPeriodReportMode` can resolve the same deep link. This exception does not authorize `getDraft`, `saveDraft` or an unissued term. The snapshot retains subject names, order and comments, plus school colors/name, student name/admission number, class, session and term names; the issued record has `issuedAt` and `issuedBy`. Graded certification rejects narrative mode. Both `getExamEntrySheet` and `upsertAssessmentRecordsBulk` reject narrative mode before exposing a score sheet or writing marks. UI must route to per-subject comments instead of these score endpoints.

B3 must call `getPortalReportSelection({studentId, sessionId, termId})`, which authorizes the linked student or guardian and returns `{mode, classId, issued}`. For narrative mode and `issued: null`, show only a neutral not-ready state. Do not fall back to scores or read draft content. `getIssuedForPortal({studentId, sessionId, termId})` returns only an issued snapshot or null. Apply this gate to selected views, dashboard, results, history, notifications and print. B1 has not edited `portal.ts` or any UI. An existing issued graded card supplies the historical class for inactive sessions without promotion records; the resolver checks student, school, session and term before using that class and still validates class ownership. For a transferred-out source student with no promotion or issue, the retained source class is historical membership evidence even when the session is inactive. The resolver still checks class ownership and mode before any graded report builder runs. An unissued narrative period returns only the neutral not-ready result. The existing graded parent publication policy remains a separate integration task.

The class/session mode, draft and issued schema are in `packages/convex/schema.ts`; all three new tables have `by_school` indexes and entries in the tenant purge manifest. The tenant purge test verifies target records disappear and another school's records survive. Seed reset also removes all three. Branch split copies class/session mode settings with class, session and actor IDs remapped, but deliberately does not copy private drafts or issued snapshots, consistent with the existing issued graded report exclusion. Wrong-branch class cascade drains up to 25 rows from each narrative table per invocation before deleting a wrong-branch class; the caller retries the same class until none remain. A test covers 110 draft rows. This does not change existing cascade limits for other tables. Drafts have a composite subject index and are bounded by the student's applicable subject list. An issued snapshot contains at most 100 subjects.

The new `by_classId_and_sessionId` index on the pre-existing `issuedReportCards` table is staged for a nonblocking first-phase backfill. Current code does not query it. Mode lock checks scan the existing school index once per request with a 1,001-row bound: over 200 issued cards work, but over 1,000 lifetime graded cards fail closed with `Report history exceeds mode-change scan limit` even for unrelated classes. No partial scan can unlock a mode. This is a remaining release limitation for larger schools. Production needs a second deployment after backfill completes: remove `staged`, switch the mode guard to query the ready class/session index, then remove the school-scan ceiling. Deploy and backfill have not been verified here. `packages/convex/_generated/api.d.ts` already includes the narrative module; Convex codegen requires a configured `CONVEX_DEPLOYMENT` to regenerate it.
