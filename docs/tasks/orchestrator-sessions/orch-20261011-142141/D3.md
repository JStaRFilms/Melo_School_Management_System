## Required design
- Derive requester from server identity; parent role only. Recheck selected school and linked child authorization on request, draft, submit and admin grant. Students cannot access this workflow.
- Scope own first/middle/last name, phone/address and approved linked child name/birth date/gender/address fields. Exclude auth email/password/identifiers, class/session/subjects/results/fees/household links, other contacts and unrestricted documents. Admin grants allowed field/target list, never blanket schema writes.
- Current live profile unchanged while draft exists. Parent reviews actual changed fields before final submit.
- Final action warns prominently: "These changes take effect immediately. You cannot edit again until an admin approves a new request." Require acknowledgement.
- Success atomically validates scope, ownership and baseline revision, applies allowed changes through corrected B1 helpers, and consumes the editing grant. Failed/stale validation does not consume a successful-apply claim or silently overwrite newer admin changes. Submitted payload immutable, further edits require fresh request.
- No second admin review state. Admin has post-submit audit and grant/revoke controls, not an approval queue for already submitted changes.
- Preserve auth/person linkage, promotion/subjects, address inheritance, tenant boundaries and issued snapshots.
- Server-only recoverable drafts, no passwords/uploads; grant/target revisions validated. Duplicate submit is idempotent; revoked permission and unlinked/moved child fail closed.
- Exact states, minimal schema/draft/API contracts, existing capabilities or narrow additional ones, portal/admin entry points and focused tests. No speculative enterprise approval engine or unrelated expiry framework.
