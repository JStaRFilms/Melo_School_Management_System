# R1 capability route / API contract

Local implementation, no rollout. Supersedes the role-only H2 claims in the earlier U1b matrix. Runtime route policy is `packages/shared/src/workspace-capability-matrix.ts`; canonical names and aliases are shared with backend RBAC in `capability-contract.ts`.

## Authority rules

- A Platform identity has **zero tenant capabilities**. Platform token identity and trusted historical Platform subject identity are terminal, including when a shadow legacy school-admin row exists. Platform school/group/commercial governance and Platform-authored audit remain separate explicit functions.
- Any role assignment, direct grant, direct restriction or delegation ceiling makes an account permission-managed. All public permission writes persist `branchMemberships.permissionsManagedAt`; clearing configuration cannot restore role-only compatibility. No automatic role seeding, cutover or migration is performed.
- Managed access is template union + direct grants − canonicalized restrictions. A linked legacy `admin`/`isSchoolAdmin` flag cannot override it. Proprietor ownership remains protected from ordinary permission editing.
- Untouched legacy accounts retain existing role/teacher-assignment compatibility on old APIs only. They do **not** receive the whole sensitive catalog. Canonical configuration is never treated as an untouched account merely because it has a legacy projection.
- `getAuthenticatedSchoolMembership` requires a reviewed operation capability for managed callers; omitted capability fails closed. Its only explicit membership-only callers are shell branding and draft ownership resolution; drafts then enforce their registered form capability. Lightweight academic selectors allow one of the closed academic-context capabilities, never bank, child or draft payloads.
- Admin/Teacher shells check the route matrix before branding/domain subscriptions and child mounting. Navigation uses the same decision. Unmapped routes/APIs deny managed accounts rather than reverting to coarse admin authority. All branch switching remains disabled.
- A route permission is not permission for all its buttons. Mutations, action dispatch, export and storage independently recheck their operation. Legacy role and teacher-assignment checks are retained as additional domain boundaries, not capability substitutes.

## Storage authority boundary

`assetStorageBoundary.ts` reuses the existing indexed asset/upload/rollback/candidate claim checks. Student photo and school-logo attachment/read/delete, report/extra/Portal image reads, and knowledge source-file signing cannot rebind, sign or delete a separately governed asset object. Knowledge finalization checks this boundary as well. This closes alternative transports around asset capability/quarantine/hold gates; it is **not** an upload entitlement, ownership-callback or quota reservation implementation (Critical 4 remains).

## Explicitly unavailable

- Unmapped legacy routes/APIs, including coarse Admin leadership promotion/demotion, deny managed accounts. The legacy admin-creation action explicitly requests unmanaged compatibility; it cannot mint a new privileged legacy account for a restricted managed actor.
- Platform `/schools/[schoolId]/migration` now renders an unavailable notice and does not mount or subscribe to private staging.
- Platform tenant support/break-glass/recovery execution is **not enabled**. There is no grant consumer and no implicit support fallback. Purpose-bound, expiring, school-scoped, single-use approval and proprietor-visible attempt/success/failure audit would be prerequisites for adding such an operation. No authorized support-grant/recovery fixture or expiry/replay claim is made here.
- None of these rows enables branch switching, private AV delivery, PDF promotion, paid providers, deployment or historical migration.
