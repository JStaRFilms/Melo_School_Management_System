## Rate, cadence and snapshot decisions

- `foundation/commercialContract.ts` owns the shared validator/calculation and **single approved seed value**: Core / Basic NGN 100,000 minor/student/term and 3,000,000 minor setup (₦1,000 + ₦30,000). Existing exported constants and the Platform seed form use it. It is a proposed catalog entry, not a hidden fallback; no catalog seed was executed outside in-memory tests. No Standard/Premium/Enterprise price was invented.
- Prices are stored in currency minor units; non-NGN UI does not assume a two-decimal currency exponent. No FX conversion, tax calculation, annual discount, provider fee or Melo collection surcharge is injected. Zero minimum/discount means none until explicitly configured.
- Whole-roster volume rate = highest matching threshold. Recurring base = max(count × rate, minimum); optional daily contract-overlap/reference-period fraction; then explicit basis-point discount. Integer arithmetic rounds half-up; setup is outside discount and proration. Total overflow rejects.
- Supported cadences: explicit term periods and annual-upfront reference periods (365/366 UTC days). Dates are UTC midnight, end exclusive. No-proration requires the entire period covered by the contract; daily means covered contract days / reference-period days. It is **not** historical enrollment or per-student arrival/departure proration.
- Billable policy `active_unique_user_v1`: students table only, explicit `enrollmentStatus=active`, nonarchived student, nonarchived same-school class, nonarchived same-school user with student role, deduplicated by user ID. Applicants, unclassified legacy rows, graduates, withdrawn/transferred-out, archived, missing/foreign links and duplicate user rows do not count. Snapshot IDs persist in child rows; later edits cannot change issued counts or amounts. Different user IDs that represent an unreconciled duplicate person require identity review; this does not claim automatic duplicate-person resolution.
- Snapshot is taken **now** within the current period. Past/future period issuance is rejected; no retrospective attendance/enrollment reconstruction. >500 source roster rows fail closed; no partial financial invoice. Contract/invoice review bounds are 500; workspace lists explicitly show recent 100 only.
- Setup handling: charge once (only if no prior positive setup invoice), explicitly previously paid with review reference, or explicitly waived for this contract. Charging does not mark a payment received. Invoices remain recorded `issued_unpaid`; no settlement/collection is inferred, including from a browser return.
