# U2a — Grading policy/editor

**Implementation delivered and locally verified; runtime acceptance pending (E0).** U2b follows this policy contract and is delivered in [U2b.md](U2b.md). No live Convex/codegen/deploy, migrations/backfills, credentials, providers, production actions, commits or browser sessions were used. Pre-existing U1 work was preserved.

## Policy and compatibility contract

- The existing **six-band** `FACTORY_DEFAULT_GRADING_BANDS` was moved, not recreated, to Shared `exam-recording/grade-policy.ts`. The backend reexports it. Admin's obsolete five-row `STANDARD_DEFAULT_GRADING_BANDS` now clones that same factory collection, including E and the factory's original ranges/points/remarks. Restore is an unsaved, reversible edit, never an automatic database reset.
- `gradingBands` remains the policy record source. Both `saveGradingBands({schoolId?, bands, expectedVersion?})` and `updateGradingBands({schoolId,bands,expectedVersion?})` call the same typed transactional writer and keep their legacy ID-array return. Inputs retain score/letter/remark and add optional `colorHex` and `gradePoints`; omitted colors/points preserve the prior matching band's values. A new uncolored custom label uses neutral ink, not a per-letter guess.
- Both writers require active branch resolution plus `academic.grading_bands.manage` (the existing alias remains normalized by RBAC), reject Platform-only writes and missing reviewed legacy staff projection, and never invent an actor/user. Scores must be integer contiguous 0–100 intervals, without gaps/overlaps/duplicate labels; hex is strictly six digits. Failed validation leaves the old policy intact. Previous bands are deactivated, not deleted; version allocation considers historical versions as well as current records. New UI supplies the loaded revision; optional revision remains only for backward compatibility with older clients.
- `getActiveGradingBands({schoolId?})` preserves legacy default-school invocation and returns effective persisted documents, including optional color/point/version fields. Empty remains empty: no synthetic IDs or silent policy installation. `getGradingBands({schoolId})` now authenticates target membership and reads the same resolver; its pre-existing empty-school factory-suggestion behavior remains distinct from an installed active policy.
- Shared `GradingBand`, Admin/Teacher response types and Admin drafts carry `colorHex`/legacy `color`, points and version. Conversion/calculation seams preserve the hue. Shared derived assessment output carries optional hue without changing grade/score math.
- `gradeDisplayColor` strictly validates hex, preserves the stored hue, and derives darkened display ink using shared luminance math. Target is **7:1 against white**, retaining >=4.5:1 headroom on the existing subtle table surfaces. `resolveGradeColor` matches the actual configured label; unknown/no-policy labels are neutral. No tenant-brand or status palette change.

## U1f grading adoption

U1f supplied branding governance and explicitly left grading unimplemented. This packet extends its **typed, explicit-choice** approach without inventing a generic settings blob:

- Additive `schoolGroups.gradingDefault = {schoolId, version, allowBranchOverride}` references immutable grading rows; it does not duplicate a preset or copy bands into group settings. `schoolGroupBranches.gradingMode?: inherit|override` records explicit adoption. Added `gradingBands.by_school_version` index.
- `resolveEffectiveGradingBands(ctx,schoolId)` is an internal helper; its caller must establish branch/assignment/family authority. Merely linking a branch **does not opt it into inheritance**. Explicit inherit resolves the referenced version, even after source branch edits. Explicit permitted override uses branch bands. Disabling overrides suppresses an explicit override, but does not silently migrate a never-opted-in legacy branch. Inactive/absent group default resolves local policy.
- `getPolicyGovernance({schoolId})` is capability-scoped metadata. `setGradingInheritance({schoolId,mode})` requires canonical branch membership/capability, active group/default and allowed override; it returns the resolved bands so the editor updates immediately. `publishGroupGradingDefault({schoolId,groupId,allowBranchOverride,confirmation})` requires recorded canonical proprietor **and** explicit source-branch membership/capability, exact group slug, and saved unambiguous versioned rows. Old duplicate-version data cannot be published without first saving a new version. All domain writes append permanent audit events.
- Real Admin grade settings UI includes group source/version, explicit inherit/override controls, dirty-state guard for source changes, and proprietor-only group publication with slug confirmation. This is targeted configuration, **not operational branch switching**. Other U1f domains remain unchanged.

## Editor

Actual `/assessments/setup/grading-bands` now uses typed generated references and U1a's validated branch. Loading, capability denial, unconfigured, dirty, invalid, saving, failed-save/retry, discard/latest and factory restore states are present. Desktop and mobile rows have curated swatches (from the one factory palette), native picker, editable hex, safe preview, and accessible field/delete labels. Saving and inherited policies disable row editing. Clean server updates refresh the editor; dirty updates retain local edits and stale saves reject. At 320px, toolbar controls stack instead of overflowing; native keyboard controls remain usable. Browser-close dirty protection is retained. Full shared router/account/branch departure integration remains U3a's seam, not a new local draft system.

## Historical/issued boundary (implemented with U2b payload adoption)

- `ReportCardSheetData.gradingPolicy? = {version, source: current|snapshot|historical_missing, bands:[{gradeLetter,minScore,maxScore,remark,colorHex?}]}`; optional `certifiedAt` marks an issued copy.
- Existing code had no immutable full-report issuance store. Additive `issuedReportCards` stores the validated report and policy snapshot by student/session/term/class, with issuer/time and original private media storage references. The report validator was moved to pure `foundation/reportCardContract.ts` for schema/query reuse and reexported at its old module path.
- `certifyStudentReportCard` and its real Admin report-panel control explicitly require `academic.report_cards.publish_final`, normal branch/report access, admission-number confirmation, complete results, a saved policy version, and an exact reviewed-content key. The key excludes volatile timestamps/media URLs; it is a conflict detector, never authorization. Server recomputes and compares before issuance. Repeat certification returns the existing issued copy; later configuration, scores, extras or comments cannot replace it. Original media references are re-signed after audience checks, never substituted from today's profile.
- Report builder returns an existing issued snapshot **after** normal student/session/class/teacher or Portal audience checks. Without one, inactive sessions/terms or ended terms use `historical_missing` and **no current grading bands**. Available recorded score/letter/remark survive; derived historical cumulative/aggregate grades without a policy use existing no-band text fallback rather than guessed current thresholds. Current uncertified previews use effective policy and are labeled accordingly.
- No historical backfill, correction/reissue lifecycle, or automatic certification on print was introduced. Issued copies intentionally do not track subsequent manual edits. Printed previews are not falsely described as certified.
