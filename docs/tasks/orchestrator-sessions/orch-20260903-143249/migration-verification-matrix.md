# Migration and Data-Contract Verification Matrix

**Status:** Proposed; execute only after program approval, PR #21 merge, fresh branch, and M0 baseline.
**Production policy:** production is read-only. This matrix authorizes no command, deployment, mutation, or export import. It describes gates for the established Convex tooling operator to execute safely.

## Universal protocol

Every listed change follows **expand → compatibility → backfill/rehearsal → verify → enforce → contract later**. New fields begin optional, old and new readers coexist, indexes deploy before their queries, and backfills are internal, bounded, cursor-based, idempotent, retryable, and durably progress-tracked. A failing migration stops the next phase; no operator “fixes” it by editing production data.

### PR-M0 prerequisite: safe development refresh

| Gate | Required evidence / stop condition |
|---|---|
| Scope | The refresh is needed for migration rehearsal only, not product implementation or production change. Use established Convex export/import tooling; do not invent raw database access. |
| Preflight | Confirm PR #21 merged and branch starts from updated `master`; read deployment names/IDs from configured tooling without recording secrets; verify **all** apps, Convex functions, scripts, and terminal target resolve to development before any replacement. Confirm production role is read-only and no deploy/mutation operation is queued. |
| Development backup | Create and verify a complete development backup before replacement; record non-sensitive manifest/checksum, timestamp, deployment identity, table/storage count summary, and restore procedure location. Abort if backup cannot be independently read/validated. |
| Read-only production snapshot | Take/read an authorized production snapshot using a read-only path; do not write production, rotate credentials, or run production migrations. Keep export outside repository and access-controlled. |
| Development refresh rehearsal | Restore/import only into confirmed development; inspect target again immediately before irreversible dev replacement. Reconcile manifest counts, referential samples, storage metadata count, and canonical identity/tenant samples. No secrets, exports, PII, or screenshots are committed. |
| Apps and verification | Confirm test/browser apps point to development; authorized main admin/main teacher credentials may be consulted only from `tmp/demo_school_credentials.md` and are never copied. Do not run destructive global Playwright setup against shared data unless separately authorized. |
| Rollback | Restore development from the verified pre-refresh backup; preserve the failed import manifest/logs outside git. Production has nothing to roll back because it was never mutated. |

## Enforcement/contract retirement gate

A legacy field/function/reader is eligible for removal only when: (1) migration progress is complete and independently reconciled; (2) compatibility-reader use is zero for an agreed observation window; (3) every dependent app/action/job is on the new contract; (4) a restore/forward-fix drill passed; (5) security, finance, and legal owners approve where applicable; and (6) removal has a dedicated reviewed PR. No contract retirement is bundled with its initial expansion.

## Migration acceptance record template

For each MX item, attach to the milestone review: deployment target proof; change/version ID; source/target counts (non-PII aggregate); duplicate/orphan/referential checks; expected/actual audit entries; focused test output; rollback/forward-fix decision; dashboards/screenshots stripped of PII; reviewer signoff. A failed item records the stop point and remains incomplete.
