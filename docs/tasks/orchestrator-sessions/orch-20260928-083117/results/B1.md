# B1 backend handoff

Implemented a separate graded class-release record, admin-only reasoned exclusions, and an atomic release that freezes each included student and their issued report ID. The release checks the full bounded roster and a fresh SHA-256 review token inside the write transaction. A retry with the original token returns the original release without another audit event. No existing report is grandfathered. Certification remains a separate staff operation.

`getReleasedGradedReport` is the B2 read helper. Call it **only after portal authentication and student access checks**, and only after resolving narrative mode independently. It returns null unless the exact tenant/class/session/term has one release, the student has one frozen inclusion and its pinned issued graded snapshot still matches the tuple and policy snapshot. It does not build or return live marks. Later draft selections, scores, promotions or additional issued rows cannot change the pinned card or hide it. Read-time tenant and student identity checks remain; an archived student is still withheld under the existing portal access policy. Archiving a class, session or term after release does not hide historical issued copies. Archival still blocks new releases. B2 must perform its own safe image URL hydration. Do not deploy B1 alone: the existing `portal.ts` still exposes draft results until B2 replaces that path. The schema and default-deny family gate must ship together.

The roster is conservative. It collects current-class candidates, promotions, selections, assessments, issued reports and exclusions; it rejects conflicting class evidence, missing enrollment/term evidence, withdrawn/transferred/graduated or archived candidates without explicit exclusion, invalid or duplicate snapshots, and empty/all-excluded rosters. A current class assignment alone is never proof of historical membership. Historical sessions without a matching promotion remain blocked even when old assessment and selection rows exist. This is intentional: the data model has no authoritative dated term enrollment roster. Schools need a reviewed historical enrollment reconciliation/import before these classes can release. A missing versioned historical grading policy still needs its separate reviewed reconciliation workflow; do not use today's bands. Limits are 80 candidate students, 512 school student rows and 512 rows per evidence source. Larger schools need a reviewed staged roster/freeze design; the mutation cannot release a partial class. Exclusions do not resolve missing/contradictory enrollment or duplicate snapshots. Post-release changes and new students do not enter the frozen roster. Read-time checks rely on the frozen inclusion and pinned issued ID, not mutable draft evidence. A reviewed amendment workflow is out of scope.

Added the tables to tenant purge and school-split purge manifests and demo cleanup. Branch duplication intentionally does not copy releases or exclusions to a destination school. The generated API declaration includes the new module; normal Convex codegen will regenerate it. There is no backfill. Rollout messaging must warn schools that previously visible drafts and already certified reports disappear from family screens until explicit release.
