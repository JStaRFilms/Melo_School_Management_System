# B4 family graded results UI

The portal now uses `selectedResultState` for the selected-term dashboard, Results and report-card sheet. A withheld term never borrows an older history average or report action. The neutral withheld and no-eligible messages follow `design.md`. The printable sheet and toolbar render only for a selected released card that matches the workspace child and, when present, the exact selected history tuple's session, term and class labels. Older released history remains available in the Results desktop/mobile lists, dashboard and report-card sidebar. Pending-subject copy no longer appears in the selected snapshot. Report-linked notifications are suppressed unless the selected card passes the released check; independent school events remain.

Navigation to another child or term clears academic content immediately, before the URL changes. A query response whose selected IDs do not match explicit URL IDs renders `Loading results...` instead of cached grades, history, notifications or print controls. A route error renders a neutral retry message with no academic payload. The backend gate still owns authorization and the exact report tuple; the printable report contract currently has no session/term IDs on the sheet, so the UI checks its child ID and checks the matching selected history row's names and class when that row is present. For direct older URLs outside the bounded history list, the backend gate is the source of truth for the term and class. The typed selected state is now part of `PortalWorkspaceData`.

Files changed: `apps/portal/lib/portal-types.ts`, `apps/portal/app/(portal)/components/portal-workspace/PortalWorkspaceContent.tsx`, new `apps/portal/app/(portal)/error.tsx`, and new `apps/portal/__tests__/result-publication-ui.test.tsx`. No Convex files or FR-023 worktree files were edited for B4.

Verification passed: portal `typecheck`, targeted ESLint, seven portal UI tests, `git diff --check`, and `node scripts/audit-theme-colors.mjs`. Tests cover withheld dashboard plus older released history, desktop/mobile results, history selection, print controls, no-eligible state, child navigation and result notifications. The theme audit is informational. Existing portal emerald, amber and rose classes are semantic status/grade or billing colours, while slate and white are product neutrals and print paper. No new tenant branding colour was introduced. The audit also lists concurrent Admin colours and existing Convex product defaults, outside B4 scope.

FR-023 integration still needs a joint typed report-mode contract and graded/narrative tests before merge. This B4 change does not render narrative reports. No commit, push or deployment was done.
