# C2 portal correction

The graded portal card now looks up a frozen inclusion by school, student, session and term. It rejects multiple inclusions for that term, checks the exact class release and pinned issued card, and rejects a second issued card for the same student/term. The selected card no longer depends on the number of other classes released or the history budget. Release writes now freeze the tuple and release timestamp on each inclusion; the read helper verifies those fields against the publication and issued snapshot.

History reads at most 48 of that student's latest inclusions by release time, validates each candidate through the same gate, and returns at most the requested 1 to 12 released rows. An older selected card remains readable even when outside those 48 candidates; the sidebar may be partial and has no pagination yet. Explicit session/term selection uses point reads rather than a school-wide 256-term scan. Default session/term selection still has bounded fallback scans for inactive sessions and non-active terms, so very large calendars need a separate selector/pagination design.

Tests cover 40 unrelated class releases, 260 unreleased terms, 55 released terms with an older selected card, duplicate same-term frozen classes, invalid IDs, another school's release, late students, archived class reads and old draft-only transfer history. The existing transfer test now expects no unpublished source-history row. No FR-023 code or UI changed. Narrative mode still needs the typed, issued-only integration before these graded reads can share a workspace response with FR-023; do not use graded fallback for an unpublished narrative term.

Verification: 64 Convex test files, 483 tests passed; `corepack pnpm --filter @school/convex typecheck`, targeted ESLint on touched backend files and `git diff --check` passed. No commit, push or deployment.

Rollout: the two new inclusion indexes must be queryable before switching portal reads to them. On an existing large table, stage and backfill indexes before activating the queries. Existing inclusion documents without frozen tuple/timestamp fields need a reviewed migration or explicit re-release plan; never infer their class from a student's mutable class. Do not deploy this handler before the schema and data are ready. The C1 `no_eligible_record` limitation remains: absent independent, score-free proof of historical enrollment, a selected but unpublished or ineligible tuple returns the uniform `withheld` state rather than claiming no eligible record.
