# PR #88 P2 event notification correction

The Portal workspace now reads upcoming school events through the existing `by_school_and_start` index, starting at the client's current time. It examines at most 64 future rows and shows the first three non-archived events in start-date order. The Portal client passes that time to the Convex query and refreshes it every minute and when the window regains focus. No server clock read, graded release gate, selected report or history logic changed.

A Convex integration test inserts 270 past events, an archived future event, another school's future event and two newly created upcoming events. The parent sees only their school's two upcoming events; advancing the supplied time removes the expired one. Current Portal clients supply the time argument. Legacy callers can omit it: the backend skips time-based school-event notices without a server clock read, while the same graded release gate and academic history remain available. A compatibility test checks withheld and released cards through a no-`now` query and verifies that only the timestamped query shows the upcoming event.

Verification passed after the compatibility change: Convex typecheck and all 487 tests across 64 files; Portal typecheck and all 7 Portal tests; targeted Convex and Portal ESLint; `git diff --check`. The informational theme audit flagged existing Portal semantic status colours, product-neutral selection/focus colours and the existing product-neutral fallback theme values in `portal.ts`. This change adds no colour. The audit also reported Admin rose status colours from the separate P1 edits; P2 did not touch Admin.

`now` is optional for backend-first rollout. Old cached Portal bundles remain callable but receive no event notices until they refresh; newer bundles keep their minute/focus time updates. The 64-row future-event cap may omit an event if more than 64 earlier future events are archived; pagination or an archive-aware index would be needed for that case. No commit, push, merge or deploy.
