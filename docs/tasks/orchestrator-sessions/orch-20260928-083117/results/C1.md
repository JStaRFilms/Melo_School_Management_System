# C1 backend correction

New graded releases now require an active session and active term. Inactive periods fail with a historical-roster reconciliation error even if all known students have issued cards: legacy evidence cannot prove that a former zero-record student is absent. Existing frozen releases remain readable and Admin can inspect their archived class/session/term. New releases still reject archived tuples.

Readiness now gathers bounded current-class students (including those without scores), promoted-to/from students, class/session selections, exact sheet assessments, exact class/session/term issued cards and tuple exclusions using indexes. Per-candidate checks still read other-class evidence to block conflicts. Missing scores do not remove a current student from the denominator. An admin can exclude a no-score student only after class/session subject enrollment is verified, with a reason and audit event. Readiness rows also provide `reasonCode` and `canExclude`; existing `reason` text remains for current UI callers. Large classes and evidence sets still fail closed at the atomic limits.

`setReleasesPaused({releasesPaused, reason})` lets a school admin pause or resume new releases. The transition writes a school-scoped control and audit event in one mutation. The release mutation reads that control inside its transaction, including for direct API calls; retries of an already released tuple remain idempotent. No setting means unpaused. The Admin context exposes `releasesPaused` and turns off `canRelease` while paused. Rollback: pause new releases for each affected school, retain the default-deny family read gate and already published snapshots, then roll forward with a fix. This is not revocation or an emergency hide-all switch. Transition audit events record actor/time/action; the control row keeps only the latest reason, not a historical reason per transition.

Verification: `corepack pnpm --filter @school/convex typecheck`, the focused publication/report-card/portal-gate/foundation suites (22 tests), targeted ESLint and `git diff --check` passed. The focused suite includes a >512-student school with a small class, no-score current students, unknown historical students, archived reads/new-write denial, and a direct-call pause.

Limitations: this is a conservative *present-day* active-term roster contract, not a signed term enrollment roster. A student who left the class without any surviving selection, assessment, promotion or issued row cannot be discovered; schools must reconcile such cases before publication. Class changes within an active term with contradictory evidence block release. Older periods need a separate authoritative import/reconciliation workflow before new releases. The new `issuedReportCards.by_class_and_session_and_term` index must be backfilled and queryable before enabling these functions on a large existing deployment; stage/backfill then activate it as separate deployment steps rather than deploying this code against an unavailable staged index. Admin selectors still cap at 256 sessions/terms/classes/releases, and a school above that limit needs paginated selectors. The pause control has no UI here; B3 must consume `releasesPaused` and the new reason codes. FR-023 narrative integration remains separate.
