# B2 graded portal gate

The portal workspace no longer calls the live graded report builder. It checks portal membership and student access, then resolves the student's historical class from the released frozen inclusion and matching issued evidence. A single class is required for the term. The read checks for a release before loading issued report contents. B1's `getReleasedGradedReport` checks the exact school, session, term, class, frozen inclusion and pinned certified card. The portal rehydrates only the pinned card's image storage IDs. An ambiguous same-term class, missing release, excluded student or late student returns no report. Explicit session/term mismatches and unknown IDs error instead of selecting the active term.

`selectedResultState` is `released`, `withheld` or `no_eligible_record`. Withheld terms have no selected card, score-bearing history row, pending-score notice, comment notice, or report link in the fallback notification. History contains released reports only, scans bounded school terms before applying `historyLimit`, and includes archived historical terms. The school session/term scan caps at 256; exceeding it fails closed and needs a paginated release-index design. Existing school-event and billing logic remains independent. Existing hard-coded portal theme colours `#020617` and `#2563eb` are product defaults, not tenant branding; the informational theme audit identified them and no global replacement was made.

Changed `packages/convex/functions/portal.ts` and added `packages/convex/functions/academic/__tests__/portalResultGate.integration.test.ts`. The Convex fixtures exercise parent and student membership, partial drafts, certified but unreleased reports, frozen results after later edits and promotion/class archival, older released history behind withheld terms, ID and tenant/family denial, ambiguous classes, excluded and late students, history limit and scan bound. B1's publication fixtures remain unchanged.
