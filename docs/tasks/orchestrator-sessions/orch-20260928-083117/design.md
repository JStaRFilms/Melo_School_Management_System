# Graded result release UI contract

This is the implementation reference for the Admin release controls and graded family result states. Certification makes a student's report immutable. It does not publish it. A school releases a reviewed class, session and term separately. FR-023 owns narrative reports and their issuance UI; do not apply this graded release state to narrative cards.

## Admin: class release

Place a "Class result release" entry beside the existing Admin report-card workflow, not in Teacher and not inside a single student's certification form. Keep the report-card page's student preview and class navigation. The release view has three persistent selectors at the top: school context shown as read-only, then session, term and class. Changing any selector closes confirmation, clears any typed exclusion reason and shows loading until readiness for the new tuple arrives. Never carry a previous tuple's green state or release action forward.

Layout, top to bottom:

1. Heading "Class result release", a one-line explanation: "Certify each student's report, then release the reviewed class results to families." Show the chosen school, class, session and term immediately below the selectors.
2. A status panel. Before release, label it "Not published" regardless of how many cards are certified. Show four labeled figures: "Eligible", "Certified", "Missing certification" and "Excluded". These are roster figures, not scores. Under them, show "Families cannot see these results until this class is released." A ready panel says "Ready to release" only when the server's full readiness check succeeds. An empty, uncertain or incomplete roster is blocked, never a green zero-of-zero state.
3. A roster with columns "Student", "Status", "Reason" and "Action". Display each student's name and admission number for staff disambiguation. Status text is "Certified", "Needs attention" or "Excluded"; don't use color alone. A blocked row names the server-provided cause in plain words, such as "Report not certified", "Missing prior-term scores", "Historical grading policy unavailable", "Enrollment needs review" or "Conflicting report records". Link a fixable row to its existing student report-card review with the same class/session/term context. For historical policy or ambiguous enrollment, show "Contact your school administrator for review" instead of promising that today's policy or a guessed class can fix it. Excluded rows show their reason and approver to staff. Keep pagination or bounded roster navigation visible; counts always refer to the entire reviewed roster, not the current page.
4. A footer with the release action. Show "Review release" only to an exam officer or other staff member with the existing publish-final capability. A school admin has a separate "Exclude student" action on an eligible row. An exam officer can read exclusions but cannot create, edit or approve them. Other viewers see the status and roster with no release or exclusion action. An already released tuple has no release or exclusion editor; show its original timestamp, actor and frozen counts instead.

### Exclusion review

The admin-only "Exclude student" action opens a dialog naming the student, admission number and exact class/session/term. Require a nonblank specific reason in a labeled multiline field. Copy: "This student will not receive this class release, even if a report is certified. The decision is recorded for review." Buttons: "Cancel" and "Confirm exclusion". On save, refresh the whole readiness roster and counts and announce success. Show the recorded reason and approver in the row. No bulk exclusions, silent omissions or exclusion checkbox in the release dialog. If the server rejects the decision, retain the typed reason and show its error beside the field. A correction to an approved exclusion must go through a separately audited review, not an inline toggle.

### Confirmation and outcomes

Disable "Review release" while loading, blocked, missing a fresh readiness review, submitting or already released. Beside a disabled control, state the reason in text, for example "3 students need attention" or "Roster needs review". On click, open a focus-trapped dialog with the heading "Release class results?" and an explicit summary: school, class, session, term, eligible count, certified count and excluded count. Copy: "Families of the eligible students will be able to see their certified reports. Excluded students will not receive this release. The released roster is frozen. Later admissions or corrections need a separate reviewed process." Add a labeled checkbox: "I reviewed this roster and understand that releasing it makes these reports visible to families." Buttons: "Cancel" and "Release class results". The final button stays disabled until checked and the review is still current; the client must submit the fresh review token, not infer readiness from counts. Do not describe this as timed, reversible or automatic publication.

During submission, disable repeated clicks and say "Releasing results...". If readiness changed, close no context: show "The roster changed. Review the updated list before releasing." Refresh readiness, uncheck confirmation and require a new review. On other failure, keep the dialog context and show a concise error without claiming success. On success, replace the action with "Released to families" plus original release date/time, actor and frozen counts. If a retry returns an existing release, show the same original event, not a second success or new timestamp. A late student or correction after release gets a staff-only "Not included in this release. A reviewed amendment is required." notice; do not imply the current screen can add them.

### Student certification copy

In `CertifyReportCard`, replace "used by Admin, Teacher and Portal previews" with: "Certification saves an immutable copy for staff review and printing. Families cannot see it until the class results are released." After certification, display "Certified copy" and "This student's report is saved, but certification alone does not publish it to families. Check Class result release for this class and term." Do not label the Admin preview "published" merely because the card is certified. Preserve the existing admission-number confirmation and historical-policy block.

## Family: exact graded states

The selected child and selected session/term own the main panel on every page. Never substitute the first history row's average, subjects, grade, comment, class or report link for the selected term. The selected-term result state is one of `released`, `withheld` or `no_eligible_record`; only `released` has a matching issued report. A loading state is separate. A direct URL with invalid or inconsistent child/session/term context must not show a different report; show a neutral unavailable state or safe navigation, not a fallback result.

| View | Withheld selected term | No eligible record | Released selected term |
| --- | --- | --- | --- |
| Dashboard `/` | Under "Term snapshot", show "Results for this term have not been published." No average, subject count, pending count, five-subject table or "Full report" link. | Show "No report card is available for this enrollment." No result controls. | Show only the issued copy's average, subjects and grades. "Full report" opens the selected released term. Do not show pending-mark language from a live builder. |
| Results `/results` | Show the same withheld message beneath "Academic history" above any older released rows. Hide the top "Open report card" action for the selected term. | Show the no-record message. Hide the top report action. | Show selected issued result and "Open report card" for that exact tuple. |
| Report cards `/report-cards` | In the sheet area, show the withheld message in a neutral card, not an A4 sheet. Hide toolbar, preview, print and download. | Show the no-record message, with no sheet or controls. | Render the issued sheet and its print controls for the exact selected term. |
| Notifications `/notifications` and dashboard Updates | Do not show pending marks, comments, grades, scores, certification notices or a result link for this tuple. School event notices remain if independent of results. | Same result-notice suppression. | Only a notification that derives from the released issued copy may link to its report. Event notices remain independent. |

Use these exact neutral empty lines. They do not reveal whether a draft or certified copy exists. An unauthenticated or unauthorized viewer must not receive a more specific message. Do not call an excluded student "waiting for certification". A school may need to explain the decision separately.

History is a list of **released, eligible reports only**. Keep the existing desktop table, mobile rows, dashboard "Recent results" and report-card sidebar, but render a row only for a released issued report with verified historical class identity. It may show that issued report's term, session, class, average and subjects and navigate to its own term. Do not create zero-score rows, withheld-term placeholders, unpublished comments or links. When empty, use "Result history will appear here once the school publishes term results." on Results, "No published results yet." in Recent results, and "No published report cards yet." in the report-card sidebar. If older terms are released but the selected term is withheld, display those older rows below the selected-term withheld card under the heading "Published past results"; no row is marked active for the withheld selection. Selecting an older row changes the selected term and then shows its issued result. The dashboard snapshot stays withheld until that selection completes. Do not pre-truncate candidate terms before finding released history.

On child or term switch, clear the old academic panel and use a labeled "Loading results..." placeholder until data for the new selection resolves. Do not display old report sheets, print actions, notification links or history as though they belong to the new child. A data error shows "Results are unavailable right now. Try again." with no cached academic values; keep non-academic billing and school events independent. Before printing, verify the selected released sheet still belongs to the active child/term; withheld and loading states produce no printable report or blank report template. White paper and readable monochrome print styles stay intact.

Narrative class-terms need a distinct renderer and issued-only narrative empty state owned by FR-023. Its unpublished narrative card must not fall through to this graded released card, even when graded assessments exist for that term. Coordinate selected-report and history discriminants in `portal.ts` with that worktree before integration. These graded strings do not claim to describe narrative issuance.

## Visual and accessibility rules

Reuse the existing Admin white/slate cards, portal neutral cards and form typography rather than adding a new brand palette. Use `@school/shared/theme` derived school tokens for tenant branding, `--school-*-contrast` on branded fills, semantic status colors for warning/error/success and the existing grade-policy colors for issued grades. Never color a withheld card as a grade or display a score-shaped placeholder. Use a 16px base text size for explanatory copy and at least 44px tap targets for actions. On desktop, put selectors and figures above the roster; on narrow screens stack selectors, wrap figures into two columns and turn roster rows into labeled cards so names, reasons and links do not require horizontal scrolling. Keep the release footer reachable after paginated rows; confirmation fits the viewport and scrolls internally if needed. No motion is needed to convey release state.

Use actual labels on selectors, exclusion reason and checkbox. Status counts have text labels; blocked reasons are announced without relying on badge color. Dialogs move focus to their heading or first field, trap focus, close on Escape or Cancel, and restore focus to the invoking button. Announce loading, readiness changes, submit error and release success through a polite live region; validation errors use an alert and point to the affected control. Links and buttons retain visible keyboard focus. Do not leave a stale enabled release button when the selected tuple changes.

## UI acceptance checks

- Certified but unreleased graded report: Admin says "Certified copy" and class "Not published"; family sees no average, subjects, comments, notifications or printable sheet across all four academic views.
- Admin-only named exclusion with reason appears in readiness; exam officer sees it but cannot edit it and can release only a fresh ready roster. Empty, ambiguous and historical-policy-blocked rosters cannot be confirmed.
- Release success and retry show the same actor/time/counts. Later students remain outside the frozen release and get no family result automatically.
- Withheld selected term plus older released term: dashboard and direct Results show withheld selected-term copy; history shows only the older released row. Only selecting that row can show its score or sheet. Desktop and mobile agree.
- Switching child or term never flashes another selection's report or result notification. Unpublished narrative with graded assessment never renders a graded card as fallback.
- Keyboard-only release and exclusion dialogs, screen-reader status announcements, narrow roster cards and withheld print behavior work without color-dependent cues.
