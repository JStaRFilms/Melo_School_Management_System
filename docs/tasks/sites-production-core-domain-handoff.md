# Sites domain and public backend handoff

Task 2 code is in this worktree. No provider, DNS, deployment, or real-school operation was performed. Task 3 must implement the fixed marker and the trusted Sites ingress before any runtime check or cutover can succeed.

## Deployment contract

The Sites production server must implement **GET `/.well-known/school-sites-deployment`** on every custom hostname, even when no school site is active. It must return status `200`, `Content-Type: text/plain; charset=utf-8`, no redirect, and exactly the UTF-8 bytes `school-sites-production-core:v1\n`. This is a code-owned constant, not tenant content. `functions/sites/providerNode.ts` connects to the hostname on port 443 using SNI and Node's trusted certificate chain and hostname verification, rejects invalid or expiring leafs, pins a public DNS address for the HTTPS request, compares the response certificate fingerprint with the validated handshake, limits the response to 128 bytes and a five-second total deadline as well as an inactivity timeout, and compares the marker bytes. DNS resolution also has a five-second bound. The server must expose the marker without depending on Convex domain activation. Do not put a marker in an editable page.

The first-party Sites server must use the actual validated request `Host`, never `X-Forwarded-Host` or `X-Forwarded-Proto`, and pass `{hostname, routeId, gatewaySecret}` to `api.functions.sites.public.resolvePublicSite` from a **server-only** action call. `gatewaySecret` is `SITES_GATEWAY_SECRET`, not browser configuration. A missing/mismatched secret, invalid hostname, unknown route, missing published profile, stale/invalid domain, publication or evidence yields `{status:"unavailable"}` with no school details. Success is `{status:"available",site:PublicSiteV1}` from `@school/shared/site-manifests`. `site.applicationLink` is the actual foundation `ApplicationLinkV1` with trusted server time; `portal` is unavailable. Only the manifest's route IDs can load. `redirectToCanonical` and `canonicalOrigin` identify a same-school active canonical HTTPS hostname; Task 3 owns safe path/query preservation for the 308 redirect. Responses must be no-store, including denied responses.

For bytes, the first-party Sites server calls the Convex HTTP site URL `POST /sites/asset-bytes` with `X-Sites-Gateway-Secret: <server-only secret>`, `X-Sites-Hostname: <actual validated Host>`, and JSON `{ "assetId": "<opaque PublicAssetV1.id>" }`. It should use the DTO's `src` as its public first-party route `/api/site-assets/<id>`. The HTTP action returns approved bytes with the asset MIME, `Cache-Control: private, no-store` and `X-Content-Type-Options: nosniff`, or a uniform 404 `no-store`. It never returns a storage ID or signed URL. It checks current publication, active host and canonical, approvals, checksum, consent, freshness and publication references both before and after fetching the blob. Do not forward that secret or this Convex HTTP URL to the browser. A public caller passing a fake clock, hostname or forwarding headers cannot acquire data without the separately configured secret. Treat compromise of this shared server secret as loss of the ingress boundary, rotate it in both deployments together.

## Configuration

`convex@1.34.1` does not support `defineApp({env: ...})`; configuration is read only from server `process.env` through `functions/sites/domainRules.ts` and the Node provider helper. No framework upgrade or `NEXT_PUBLIC` declaration was made. Configure:

- `SITES_VERCEL_PROJECT_ID`: real Vercel project ID in `prj_...` format. Never a placeholder for live checks.
- `SITES_VERCEL_TEAM_ID`: `team_...` when team-scoped, otherwise absent. Confirm account scope with the credential owner.
- `SITES_VERCEL_API_TOKEN`: private server Vercel API token, at least 24 characters, with project-domain read permission and explicit write permission only for operator attach/verify. Do not log or place in a Sites client bundle.
- `SITES_GATEWAY_SECRET`: independent random server-to-server secret of at least 32 characters on both Convex and the first-party Sites server. Never `NEXT_PUBLIC`.
- `SITES_ALLOW_PROVIDER_WRITES`: absent/disabled by default. Set **exactly** `enabled` only for a reviewed explicit live operator operation, then disable it. No calls were made here.
- `APPLICATION_ORIGIN` or `APPLY_APP_ORIGIN`: existing foundation config. Required in production to resolve the `ApplicationLinkV1` DTO; neither Host nor site content sets it.

The read-only readiness check and public gate require valid project/token settings. Activation also requires the gateway secret. Missing configuration denies, even if test records claim `ready`. The marker must be deployed on the **same production project** identified by the project ID. Set all secrets through the approved stores, not task docs or chat.

## Operations and API

School users with active same-school `site.domain.request` grant call `api.functions.sites.domains.requestDomain({schoolId,hostname,canonicalIntent})`, `getInstructions({schoolId,domainId})` and `rotateChallenge({schoolId,domainId})`. A normalized ASCII DNS name, without scheme, credentials, port or wildcard, is reserved globally in `by_hostname`, including after retirement. `requestDomain` returns the TXT name `_school-site-verify.<host>`, a random 256-bit-plus opaque TXT value, expiry and ID. Existing mixed-case legacy rows should be audited before production launch: they were not migrated and may not have normalized index keys. `getInstructions` returns `renewalRequired` when the 30-day TXT challenge has at most seven days left. Rotate and publish the new TXT value before expiry, then recheck and reactivate. Rotation intentionally takes the hostname out of service until the new ownership and provider/TLS observations pass and an operator activates it again. Expiry is a hard public denial; do not quietly extend an old TXT token indefinitely. Plan a DNS-owner renewal procedure and alerting in Task 4 before launch.

Operator actions require current active platform authentication on entry and on observation commit. `api.functions.sites.domainActions.getRoutingInstructions({domainId})` is a separate operator-authorized, read-only Vercel GET v9 project-domain, production-list and GET v6 config call for an already attached hostname. It returns bounded ranked CNAME/IPv4 and TXT verification records with record owner/type/value/reason while `verified=false` or `misconfigured=true`. It does not establish school TXT ownership, routing, TLS or readiness. Attach after fresh school TXT proof and explicit approval, fetch instructions, let the DNS owner publish the provider TXT and routing records, verify via a separate explicitly enabled provider POST if needed, then check readiness and activate. Never supply a guessed apex IP. `api.functions.sites.domainActions.checkReadiness({domainId})` performs read-only authoritative TXT, Vercel and live TLS checks; returns `{ready:true,observedAt,recommendedCNAME,recommendedIPv4}` on success. These ranked routing records come from Vercel `/v6/domains/{domain}/config`, not a guessed apex IP. Failure clears observations for that generation and leaves an active hostname unavailable until a successful recheck. The operator must separately confirm a provider attachment or verification through `api.functions.sites.domainActions.mutateProvider({domainId,operation:"attach"|"verify",confirmation:"CONFIRM ATTACH <hostname>"})` or `CONFIRM VERIFY <hostname>`, with the live-write flag enabled. That action calls respectively `POST /v10/projects/{idOrName}/domains` or `POST /v9/projects/{idOrName}/domains/{domain}/verify`. Checking status and viewing instructions never call POST. This implementation does not delete/move domains, change DNS or issue certificates. Before each POST, the server checks the fresh exact authoritative school TXT and atomically reserves the domain write. Pending or uncertain writes fail the public-readiness gate and block another provider write, activation, proof rotation, suspension and retirement. A positive read-only project/production-domain confirmation through `reconcileProvider` can release an uncertain reservation after 30 seconds; a missing provider record keeps it blocked for operator investigation. This pause is intentional. Do not interpret an action timeout as rollback of a provider side effect.

After school publication and a successful check, `api.functions.sites.domains.activateDomain({domainId,canonicalDomainId?})` atomically validates the published manifest, current digest, approved school identity/evidence/assets, operator, ownership/routing/TLS freshness, the same-school canonical and one canonical pointer. Alias activation requires the canonical ID. Use `suspendDomain({domainId})` or `retireDomain({domainId})` to deny pages, redirects and bytes immediately. Retirement keeps the hostname reserved. A suspended record cannot be resumed automatically: the school rotates its TXT proof and the operator performs a fresh check/activation under a separately reviewed recovery policy. All domain transitions write safe actor-attributed audit summaries without token or provider credential values.

The provider reader uses official unauthenticated OpenAPI extract `/tmp/sites-production-vercel-api.json`: single-domain GET requires exact `name`, configured `projectId`, `verified === true`, no `gitBranch`, `customEnvironmentId` or redirect; production-filtered project list GET requires exactly one matching record and complete pagination; config GET requires `misconfigured === false` and serving `configuredBy` of A, CNAME only. `http` proxy configuration and `dns-01` alone are insufficient without independent deployment-bound proxy proof. It does not use a guessed `tlsActive`, cert-list metadata or provider verification as school ownership proof. A project with more than 100 production domains currently fails closed because the Vercel list pagination is incomplete, rather than accepting an unproven target. Add a fully verified bounded pagination strategy before scaling beyond that limit.

`crons.ts` schedules `internal.functions.sites.domains.maintenance` every five minutes. It takes up to 20 due active domains and schedules `internal.functions.sites.domainActions.maintenanceCheck` for each. This check is read-only externally and commits only against the same generation/hash. Successful checks update active observations without transitioning the site back to `ready`; failed checks clear observations. The public action uses fresh server time and a strict 15-minute observation window even if cron lags. At more than 20 domains due per five minutes, overdue sites may become unavailable. Increase bounded capacity or shard scheduling and test load before a larger rollout. TXT expiry still needs the school DNS-owner renewal described above.
