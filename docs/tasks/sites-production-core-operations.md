# School Sites hosting and operator guide

## Configure before a live check

Use approved private secret stores. Do not copy `.env` files or paste credentials into tickets. Deploy the same reviewed build of `apps/sites` and `packages/convex` with `CONVEX_URL` and `CONVEX_SITE_URL` as HTTPS origins on the Sites server and `SITES_GATEWAY_SECRET` as the same independently generated server-only secret of at least 32 characters on both sides. `CONVEX_SITE_URL` is the Convex HTTP action origin, not the cloud API URL. Configure `SITES_VERCEL_PROJECT_ID` (`prj_...`), optional `SITES_VERCEL_TEAM_ID` (`team_...` when required), and private `SITES_VERCEL_API_TOKEN` on Convex. Set `APPLICATION_ORIGIN` or `APPLY_APP_ORIGIN` on the foundation service for actual `ApplicationLinkV1` destinations. Do not use `NEXT_PUBLIC` for provider or gateway secrets. Convex 1.34.1 does not support typed `defineApp({env})`; `functions/sites/domainRules.ts` validates server-side environment values and refuses missing configuration. `SITES_ALLOW_PROVIDER_WRITES` defaults off; set exactly `enabled` only for an approved operator attach/verify operation, then disable it. Configuration alone does not prove a hostname ready.

The Admin server upload proxy also requires `CONVEX_SITE_URL`, set to the same exact Convex HTTP action origin for that hosting environment. `NEXT_PUBLIC_CONVEX_SITE_URL` alone does not configure the proxy. A missing server setting returns HTTP 503 before any website asset upload. Verify this setting on the intended Admin Production project and deploy the environment change before testing real uploads. Do not alter Preview settings as part of a Production repair.

The production Vercel project must serve GET `/.well-known/school-sites-deployment` for each custom hostname before activation, returning exactly `school-sites-production-core:v1\n`, plain text, no redirect. Configure `SITES_PRODUCTION_CUSTOM_HOSTS` on Sites as a comma-separated deployment-owned list of exact custom hosts assigned to the Vercel production project. Keep preview and `*.vercel.app` deployment URLs out; changes to this list require deployment approval. Confirm Vercel's project domain assignments and actual Host ingress before adding a hostname. Forwarded-host headers cannot select a tenant. The static deployment marker does not prove a proxy's production-project origin. Verify the private shared gateway secret agrees on both services. Unknown or stale sites return noindex, no-store and no public bytes. Never publish a static Admin operational theme or private storage URL as a site asset. School-facing branding accepts only primary/accent tenant inputs; the synthetic public projection currently contains neither and uses derived defaults. Keep status and grade colors semantic.

## Synthetic operator sequence

1. Confirm the target is a fictional test school with properly scoped independent school editor, reviewer, publisher, DNS requester and platform operator identities. Provision only the code-owned `school-core-synthetic-v1/1` profile from the platform school site page. The school cannot choose a renderer.
2. In Admin school-site settings, save `school_name` matching the persisted school name and a short `intro`. The editor keeps unsaved content on `DRAFT_VERSION_CONFLICT`; compare before retrying. The reviewer uses `getFieldCandidate` to inspect the current digest and an independently held identity source, then records a bounded reference, the actual source kind and a dated or explicitly until-revoked approval with `privacy.approve`. Until-revoked authorization requires a source with no end date; owner attestation does not claim document inspection. Do not let the publisher approve their own evidence. Upload PNG or JPEG synthetic images only; the server decodes and writes a clean PNG with a canonical hex checksum. The byte-upload endpoint rejects WebP and unsupported formats. The explicit Admin-logo copy control can convert bounded WebP into PNG before using that same endpoint. It checks the authenticated branding response's school ID and never publishes the Admin storage ID or signed URL. A child classification starts unselected and requires an explicit choice. For an uploaded synthetic image, reviewer must independently record rights, `no_children` or `contains_children`, and child consent when needed, all bound to the server checksum. Unknown classification blocks publication. Actual evidence expiry or revocation blocks the next gate. Old finite evidence stays finite. Record replacements through the reviewer API and republish through the version-checked workflow, never patch old approvals or published revisions.
3. Use authenticated inline preview, check publication gates, then publish with explicit school-wide capability. Preview is watermarked and has no canonical URL. Publish creates a new immutable revision. Revert clones history to a private draft and requires a fresh approval check before republishing. Admin operational branding remains separate from published site content; an Admin save does not synchronize Static Sites data.
4. A school DNS requester requests the hostname, then publishes the exact returned `_school-site-verify.<host>` TXT value through its DNS owner. New requests use `ownershipProofPolicy: persistent_authoritative_v1` with no calendar deadline. Keep the exact TXT record installed for automatic authoritative checks. Unmarked legacy challenges remain finite, with `renewalRequired` in their final seven days. A platform operator can explicitly adopt a still-valid legacy proof only after a fresh passing readiness check and exact-host confirmation. Adoption preserves the TXT value, generation and active routing. Expired legacy proofs, stale observations, suspension, retirement and provider-operation locks block adoption. Explicit rotation uses persistent policy but changes the token and generation, invalidates observations and stops an active site until fresh proof and operator activation. It is not routine renewal.
5. The operator confirms the real project and production assignment. Attach and verify are two separate live provider POST operations requiring fresh exact authoritative school TXT, the temporary write flag and exact typed confirmations; viewing status and readiness checks are read-only. The write is reserved before POST. An in-flight or uncertain result takes public serving offline and blocks another write, challenge rotation, activation, suspension and retirement. Wait at least 30 seconds and use the operator's read-only reconciliation control. A missing or ambiguous provider record stays blocked; seek a reviewed manual recovery rather than retrying blindly. After the school TXT is published, attach the hostname if authorized. Use the separate operator-only `getRoutingInstructions` action and the platform's "Fetch DNS and verification instructions" button while Vercel verification, routing or TLS is still pending. It reads the exact attached production-project domain and Vercel config without changing readiness. Give the DNS owner the returned TXT verification challenge and ranked CNAME or IPv4 records, including record owner and type. Never guess an apex IP. The DNS owner then changes records. Request a separate Vercel verify POST if needed, with a fresh school TXT, write flag and confirmation. A later read-only readiness check must prove authoritative school TXT, exact verified production Vercel configuration, routable public DNS, live SNI/trusted TLS and the fixed deployment marker. After content publication and recent checks, explicitly activate canonical first, then aliases against its same-school canonical ID. Suspended and retired domains stop pages and bytes immediately; retirement reserves the hostname.

## Readiness and capacity

A fresh check lasts 15 minutes. A five-minute scheduled maintenance batch checks at most 20 due active hosts; above that bound or after delayed/failed cron, sites fail closed. Vercel production-domain listing above 100 records fails closed pending verified pagination. Local mocked tests do not verify the deployed TLS probe, network or production provider project; verify those against the actual deployment. Authoritative rechecking is automatic, but legacy adoption, proof rotation, provider writes and activation are never automatic. Confirm deployment networking, provider permissions, DNS ownership, challenge rotation operations and cron capacity before any launch. The operator status view estimates freshness at its last load; the server rechecks at activation and on every public request. Synthetic testing authority does not authorize real-school photographs or approvals. Real-school operations require separate owner authorization and truthful, school-specific evidence. The approved Olive Production work and its limits are recorded in `deliverables/obhis-hosted-launch/upkeep-results.md`.

## Current upkeep API and website icons

The [upkeep contract](../features/ManagedSiteUpkeepAndBranding.md) supersedes older mandatory 30-day Sites approval or TXT renewal instructions. It does not extend temporary access grants, TLS certificates or the fifteen-minute observation window.

- `functions/sites/evidence:approveCandidate` accepts `{schoolId, candidate, evidenceReference, confirmed: true, validity: "until_revoked", sourceKind: "owner_attestation" | "document_review"}` with no `expiresAt`. Dated approval accepts a finite future `expiresAt` within 366 days and no `validity` marker. Existing finite callers may omit `sourceKind`. Missing lifetime, contradictory date/marker, nonfinite dates and unconfirmed approval are rejected. The server recomputes the candidate digest or immutable asset checksum. The newest applicable approval wins; expiry, revocation or publisher self-approval cannot revive older evidence.
- `functions/sites/domains:adoptPersistentOwnership` accepts `{domainId, confirmation: "CONFIRM PERSISTENT <exact stored hostname>"}` from an authenticated active platform operator. Run the separate read-only readiness check first. Adoption makes no external call and does not activate a hostname. No flag enables adoption around an expired proof or a provider-operation lock.
- Admin management returns separate edit, review, standard/sensitive publish, preview, revert and domain-request flags. A read grant is not an edit grant. Reviewer and publisher controls do not depend on editing permission.
- Published `school_logo` supplies the favicon and Apple icon by default. An optional `site_favicon` asset reference of kind `favicon` overrides it. Both metadata and manifest use only the admitted, published host's first-party asset proxy. A private upload or Admin branding save changes neither. Copy the Admin logo explicitly, select the copied private logo, save, obtain independent website rights/classification/consent review, and publish. No monthly content reapproval is required solely because time passed for an until-revoked approval.

Deploy the additive schema/backend before the updated Admin/Platform UI. The existing `domains` module contains adoption, so no new API module binding is needed. No remote codegen or record rewrite is required. Deploy Sites with the same optional manifest descriptor and without `app/icon.png`, which would override tenant metadata. Old draft/publication digests and unmarked finite rows retain their meaning. After review, the release operator must record truthful replacement approvals, republish, and adopt only authorized exact domains through these APIs. Older backend builds fail closed on indefinite evidence/proofs, so do not roll back backend lifespan support while relying on those records.

## Merge and OBHIS adapter

Review the combined branch, rerun focused backend and Sites/Admin/Platform checks, then merge only through the reviewed PR. Deployments, remote migrations, DNS changes and provider writes need separate authorization. Do not move OBHIS's branch from its other computer until code and requested review docs can be transferred safely without secrets or private image bytes. Its key, version, route IDs and field IDs are external blockers, not inferred from the synthetic example. When available, add an exact `SITE_MANIFESTS_V1` entry in `packages/shared/src/site-manifests.ts`, a matching compile-time entry in `apps/sites/core/registry.tsx`, and typed readonly props from `ProductionSiteContext` (`apps/sites/core/public.ts`). `apps/sites/core/gateway.ts` alone calls `api.functions.sites.public.resolvePublicSite`; `apps/sites/core/registry.tsx` has no fallback. Approved assets use first-party `/api/site-assets/<id>` and `/apply` consumes the validated `ApplicationLinkV1.href`, never a renderer-authored origin. Portal remains unavailable. Inspect actual OBHIS content and visual contrast, identity evidence, photography rights/child consent and real domain cutover independently before approving launch.
