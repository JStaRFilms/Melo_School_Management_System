# Sites frontend handoff

Task 3 is implemented in this worktree. It has no live backend, provider or hostname verification. The build succeeds without runtime configuration because public requests deny when configuration is absent.

## Public integration contract

`apps/sites/core/gateway.ts` is the only managed-site client. It reads server-only `CONVEX_URL`, `CONVEX_SITE_URL` and `SITES_GATEWAY_SECRET` at request time. Both URLs must be HTTPS origins and the shared secret must have at least 32 characters. For pages, the server calls `api.functions.sites.public.resolvePublicPath({hostname,path,gatewaySecret})` through `ConvexHttpClient.action`; the backend selects the exact route from the published registered manifest after host and publication validation. Existing `resolvePublicSite({hostname,routeId,gatewaySecret})` callers remain supported. The gateway validates the resulting DTO and derives its route ID from the same manifest, never from a client-supplied redirect. `hostname` comes solely from the actual `Host` header and must appear in the deployment-owned `SITES_PRODUCTION_CUSTOM_HOSTS` comma-separated allowlist. Configure only custom domains routed to the production project. No preview or `.vercel.app` alias belongs in this list. Keep the Vercel production deployment's custom-domain routing restricted to these hosts; arbitrary forwarded headers cannot prove the ingress. Forwarded host/protocol headers, preview overrides and browser-provided tenancy cannot select a school. Errors and missing settings return unavailable. `CONVEX_SITE_URL` is the Convex HTTP action origin, not the Convex cloud URL. Configure matching `SITES_GATEWAY_SECRET` on Sites and Convex through their private secret stores; no `NEXT_PUBLIC` variant exists.

`admitSite` in `core/public.ts` validates the public projection against `@school/shared/site-manifests` and returns a recursively frozen `ProductionSiteContext`, a `DeepReadonly<PublicSiteV1>`. This type is separate from `PrivateReviewContext`. It includes only approved fields, first-party asset routes, route SEO, `ApplicationLinkV1` and an unavailable portal. It contains no Convex clients, storage IDs or evidence. Unknown renderer keys, schema versions, route IDs, field IDs, malformed assets and invalid SEO deny. `core/registry.tsx` contains exactly `school-core-synthetic-v1/1`, compiled to `SyntheticPage`. No OBHIS registration or substitute exists. To add OBHIS, register its actual manifest in shared validation and compile an exact matching renderer here, then map only the validated context into typed renderer props. Do not import private review fixtures into the registry.

The synthetic renderer uses `school_name`, `intro` and optional `hero_image` from the approved projection. Only home, about and contact are registered. It does not query Convex or build application destinations. The approved `ApplicationLinkV1.href` can redirect `/apply` with a noindex 307 only if availability is `open`, school slug and foundation `/s/<slug>` or `/s/<slug>/i/<intake>` path match, and HTTPS is used. Other availability states have no CTA. Portal is hidden. The present `PublicSiteV1` does not contain `primaryColor` or `accentColor`; the renderer calls `deriveSchoolTheme()` with its default inputs rather than inventing school colours. Adding tenant colours requires a separately approved, validated public projection of only those two inputs.

`proxy.ts` uses the same backend gate for managed canonical 308 redirects. Its wildcard matcher exempts framework assets, APIs, the deployment marker, technical metadata and static files, including health checks before tenant activation. It preserves validated manifest paths and safe query strings, rejects unknown slugs, encoded traversal and backslashes, and always uses the stored HTTPS canonical origin. Page metadata, robots, sitemap and manifest use the same server-side public loader. Sitemap dates come from the immutable `publishedAt`, not request time. Metadata admits only approved SEO route values and first-party approved social images. JSON-LD is escaped. Denied pages are 404 and noindex; global response headers set `private, no-store` on all paths. The fixed deployment marker at GET `/.well-known/school-sites-deployment` is independent of tenant resolution and returns exactly `school-sites-production-core:v1\n` as UTF-8 plain text 200.

GET `/api/site-assets/[id]` calls POST `<CONVEX_SITE_URL>/sites/asset-bytes` with the server-only secret, actual Host and opaque ID. It accepts only a bounded image byte response, never redirects to storage, and emits `private, no-store` and `nosniff`, including denial. Convex rechecks publication, host and rights before and after its storage read. This proxy does not optimize or cache those bytes.

Local demo requests use `legacyDemoFromHeaders` to parse only explicit `.localhost` and `localhost` Host aliases, with optional valid ports. Production hostname parsing remains strict and does not use forwarded headers. The former static catalogue and renderer were removed. `core/legacy.tsx` keeps only Greenfield and Aster local development demo names, including legacy `localhost` and `greenfield.localhost` for Greenfield, behind `SITES_ENABLE_LEGACY_DEMOS=enabled`, additionally disabled whenever `NODE_ENV=production`. They are noindex and cannot substitute for a missing managed profile on a production host. The fabricated OBHIS fixture was removed, not registered. The standalone public icons remain product-neutral assets; no private images were added.

The route-seam correction and current check results are in `sites-production-core-route-results.md`. The checks below describe the earlier frontend handoff.

## Checks and limits

`pnpm --filter @school/sites exec vitest run core` passed, 9 tests across the deployment marker, public gate, forwarding-header denial, unknown schema/routes, alias safety, foundation link consistency, SEO, byte proxy, missing configuration and legacy allowlist. `pnpm --filter @school/sites typecheck` passed. `pnpm --filter @school/sites lint` passed with one intentional `no-img-element` warning: first-party byte delivery must bypass the image optimizer cache. `pnpm --filter @school/sites build` passed with no backend environment or network; marker and asset proxy are dynamic routes. `node scripts/audit-theme-colors.mjs` ran. It listed no touched Sites files; the remaining literal in Sites CSS is product-neutral body ink. A scan of `.next/static` found no gateway secret key or OBHIS fixture reference. Server output contains server-only gateway code, as expected. No live provider, DNS, deployment, remote backend or headless hostname check was run.

A real hostname needs the Task 2 fresh readiness gate, correctly configured Convex endpoints, shared secret and an approved immutable publication. The synthetic frontend has not been exercised against that runtime. OBHIS routes, imagery and field mapping remain unknown until its other worktree is available. Management UI is not part of Task 3.
