# Managed school-site implementation handoff

Task 4 added a synthetic-only management route at `apps/admin/app/admin/settings/site/page.tsx` and an operator route at `apps/platform/app/schools/[schoolId]/site/page.tsx`. The settings tab and platform school list link to them. No real school data was entered and no live calls were made.

`api.functions.sites.management.schoolView` and `operatorView` are server-timed actions backed by bounded internal queries. The school projection requires a same-school school-wide settings.view/manage, site preview, publishing, revert or privacy approval grant, or a domain-request grant for a domain-only projection; the operator projection requires an active platform admin. The general school view returns the current typed draft, up to 20 publication summaries, 30 image summaries and 30 domain summaries. A domain-request-only user sees domains and profile identity but no draft, publications, assets or private publication pointer. They omit storage IDs, signed URLs, raw evidence references, private documents, provider tokens and arbitrary document payloads. Both action reads recheck auth; mutations keep their separate grants. The view is not permission to publish or approve.

The Admin editor uses `SITE_MANIFESTS_V1` to expose named typed synthetic fields and route SEO. Save uses `expectedDraftVersion` and keeps local edits on conflict. `getFieldCandidate` returns the exact digest and value to the reviewer; approval sends that digest or the displayed immutable asset checksum, a typed rights/child candidate, independent source reference, expiry and explicit confirmation. Review is never silently assumed from publishing rights. The reviewer must inspect an actual independent source. The child-classification selector starts blank; confirmation and approval require an explicit selection. Upload accepts PNG/JPEG only and stores a sanitized PNG. Upload goes through same-origin `/api/site-assets/upload` using `getToken`, bounded bytes and approved image MIME; this endpoint forwards the bytes to Convex `/sites/asset-upload` and returns only the opaque website asset ID. It does not expose the Convex HTTP origin or storage ID. Private preview calls `previewDraft` and displays its watermark, noindex text and placeholders inline. This is not a public share URL. History lists 20 publications; revert clones a chosen publication into a draft. Validation and publication perform independent server checks. The UI cannot select a renderer or activate a domain.

School users request a hostname and see the 30-day TXT proof and `renewalRequired` when seven days remain. Rotating an active host interrupts service pending fresh checks and activation. The operator view shows ownership, routing and TLS observation timestamps and their 15-minute freshness estimate; a read-only readiness check is separate from attach or verify. Attach and verify require exact hostname-specific typed confirmation, a second browser confirmation, platform authorization, and the server's disabled-by-default `SITES_ALLOW_PROVIDER_WRITES` flag. Provider checks do not attach anything. Activation requires a current publication, fresh observations and explicit confirmation; server validation remains authoritative. Suspension and retirement have their own confirmations. No school user can invoke those controls. No platform operator can approve school facts through these screens.

The included Admin proxy test covers authentication, same-origin enforcement, bounded MIME, opaque success response and stripped upstream errors. The synthetic UI test exercises named fields, an unselected child classification, optimistic save conflict and retained local edits with mocked authenticated hooks. Backend site and domain tests in the earlier handoffs exercise synthetic approval/publication/domain contracts independently. This is not a production-runtime E2E test. Verification here: 4 focused Admin tests passed across two files, 7 focused Convex site tests passed across three files; shared, Convex, Admin, Platform and Sites typechecks passed. Focused ESLint and full Admin/Platform lint passed without errors. Platform build passed. Site-specific admin entry now shows a configuration error instead of mounting its hooks when unconfigured. Sites lint had one existing first-party image warning. The theme audit ran; the new settings UI uses slate product neutrals and a red semantic error, no tenant colour literals. There is no configured local Convex auth, provider/TLS deployment or seeded browser identities here for a fresh authenticated headless browser run. Do not point a headless test at a remote user backend. OBHIS field names, schema version, routes and visual adapter are unknown on this machine.
