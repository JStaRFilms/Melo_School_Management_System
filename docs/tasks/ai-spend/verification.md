## Working route

- Teacher lesson plans, student notes, assignments, question banks and CBT drafts now prepare the actual prompt in a quote action. Preparation checks staff access, source selection, excerpts where required, templates, effective assessment settings and model ID. A SHA-256 digest binds the resolved request, prompt and current source/template/profile context. The attempt stores only identifiers/settings and the digest, not the prompt.
- The visible teacher review dialog shows output, source count, model, expiry, available allowance, reviewed `ai_tokens` hold and expected remaining allowance. Confirm reserves against the contract-bound cycle. Dispatch accepts only the attempt ID, re-prepares and compares the digest, checks the hold and claims once. Edits, a revoked role/capability, a changed model or changed source/template/profile stop before a provider call. The original public generation actions no longer accept actionable generation arguments.
- A single `generateObject` call uses the existing OpenRouter model and output schema with `maxOutputTokens: 2048` and `maxRetries: 0`. There is no repair call in this activation. The quote and dispatch serialize the same SDK JSON schema. The known system, prompt and schema UTF-8 bytes are capped at 16,000; a profile needs at least `known bytes * 16 + 4,096` units for the one capped call. That is a conservative hold, not a guaranteed provider maximum: provider framing and tokenizer overhead are not observable before a call. Verified overage is charged in full and blocks new quotes pending review. Provider-reported input and output tokens are checked as nonnegative safe integers. A branded SDK `NoObjectGeneratedError` with complete usage settles failed measured work once; malformed or untrusted error usage and ambiguous calls remain held for reconciliation.
- Measured calls settle exactly once, including template/count validation failures. Full over-hold usage is recorded and blocks further quotes pending Platform review. Valid generated content is staged in a separate private result table before settlement. Only internal generated-save mutations can associate the draft ID with an attempt and delete staged content. Public save mutations keep ordinary editing but reject an attempt ID. The generated save associates the result atomically and deletes staged content. If saving fails after settlement, the teacher can recover the staged result without calling the provider again. Tenant purge removes staged content by attempt. The customer event ledger and attempt do not contain generated text.
- `aiRunLogs` now references the attempt and records measured tokens once; the old caller-supplied run-log mutations are internal. Platform sees recent token/evidence records, unsettled holds and reconciliation/overage controls. Admin sees the cycle's AI allowance and usage events. Provider OCR and unrelated paid routes remain gated. No provider price is inferred from token usage and no fictitious zero-cost provider record is written.

## Independent review changes

1. Public lesson and assessment saves no longer accept `attemptId`. Internal generated-save mutations require a settled, matching attempt and staged usage. An adversarial teacher cannot replace staged content or mark a forged draft as the provider result. Existing manual edits still work; recovery is idempotent.
2. Platform unresolved attempts use a school/status/updatedAt index with bounded pages. A test inserts 150 newer other-school attempts and checks two pages from the requested school.
3. Active cycle reads use school/status rather than a 101-row history scan. Cycle creation checks indexed active rows and the latest overlapping predecessor. A test quotes, confirms and claims after 125 closed cycles.
4. A branded AI SDK schema error with complete validated usage settles as failed and emits one event. Partial usage or a generic error with an untrusted usage-shaped property remains held.
5. Quote sizing measures the SDK's serialized schema together with the actual prompt, then applies a conservative hold. The provider's unseen framing means this is not a guaranteed consumption limit. The existing full-overage settlement and Platform block remain mandatory.
6. New backend and client calls use generated `api`/`internal` references. The offline Convex API template generated the missing module entries because the CLI needs deployment configuration. No generated file was handwritten.
7. The mocked action test is a `.test.mts` file with a `vite/client` reference. This isolates Vite's `ImportMeta.glob` definition from older test declarations in the Convex `.ts` typecheck.
8. Admin readiness takes a supplied clock and refreshes every 30 seconds. The confirmation dialog shows current headroom and expected remaining tokens.

## Second review change

Overage review now uses `aiOutstandingOverageCount` on the AI meter. Each verified over-hold settlement increments it once. Platform review checks that the attempt belongs to the meter's original cycle, then decrements it once; other outstanding overages keep dispatch blocked. New cycles initialize the count to zero. No attempt-history scan or new index is needed. A test inserts 125 ordinary historical attempts, reviews two pending overages separately, rejects duplicate and old-cycle reviews, and proves the block clears only after the second review. A legacy meter marked blocked without a count fails closed and needs evidence-based migration rather than guessing the outstanding total. The AI run-log integration test now references `vite/client` and uses `.mts` to avoid colliding with older global `ImportMeta.glob` declarations. Teacher status says "Reviewed hold".

## Review and activation limits

Independent standards and spec/security reviews approved the final implementation at b9149f2 after two remediation rounds. The parent agent independently reran all 747 Convex tests, Convex and teacher typechecks, and diff check successfully. GitHub review is the next gate; live-provider verification and deployment approval remain separate. The new school/status and school/start indexes are declared ready for indexed reads; on a large existing deployment, adding non-staged indexes can block deployment during backfill. Platform must review the index rollout and, if needed, stage them in a first deploy and switch these reads only after backfill completes. No deployment was attempted. The single-call design deliberately gives no automatic template/schema repair; failed validation can consume measured tokens. OpenRouter responses without trustworthy price/currency produce token evidence but no cost row. A thrown provider error without reliable token evidence remains held until an operator checks the provider records. No automated provider-report import is provided. Settlement after a crash between dispatch and result staging also requires operator evidence; retries never send the call again. A settled staged draft whose sources or template can no longer pass the existing save policy needs an operator/content decision before recovery. The recent Platform evidence view is bounded to 100 school attempts. The unresolved view uses a school/status/updatedAt index and paginated reads; 150 newer rows from a different school do not hide this school's holds. School readiness accepts a time argument, and Admin refreshes it every 30 seconds.

After independent review, Platform must publish separate reviewed `teacher_lesson_plan` and `teacher_assessment` `ai_tokens` profiles matching the selected OpenRouter model IDs and worst prepared request bound, link the effective contract and start a nonoverlapping cycle with exactly one AI meter. Configure the provider key and approved model overrides only after cost review. Test a teacher quote, explicit confirmation, a measured event, failed-use settlement, reconciliation and zero-hold close in a controlled environment before enabling a school. A key alone grants no allowance; OCR stays disabled.
