# AI spend verification, B1

Status: **implemented for code review, not deployed or approved for live provider use**. This replaces the foundation-only report from b07a413. No live AI request, environment copy, payment, deployment, push or PR was made.

## Working route

- Teacher lesson plans, student notes, assignments, question banks and CBT drafts now prepare the actual prompt in a quote action. Preparation checks staff access, source selection, excerpts where required, templates, effective assessment settings and model ID. A SHA-256 digest binds the resolved request, prompt and current source/template/profile context. The attempt stores only identifiers/settings and the digest, not the prompt.
- The visible teacher review dialog shows output, source count, model, expiry and maximum `ai_tokens` hold. Confirm reserves against the contract-bound cycle. Dispatch accepts only the attempt ID, re-prepares and compares the digest, checks the hold and claims once. Edits, a revoked role/capability, a changed model or changed source/template/profile stop before a provider call. The original public generation actions no longer accept actionable generation arguments.
- A single `generateObject` call uses the existing OpenRouter model and output schema with `maxOutputTokens: 2048` and `maxRetries: 0`. There is no repair call in this activation. The quote needs a reviewed `unitsPerItem` at least `(UTF-8 prompt bytes + 12,000 schema/framing bytes) * 4 + 4,096`; prompts over 16,000 bytes are refused. Provider-reported input and output tokens are checked as nonnegative safe integers. Invalid/missing usage and thrown provider errors hold the attempt for reconciliation, not a free release or replay.
- Measured calls settle exactly once, including template/count validation failures. Full over-hold usage is recorded and blocks further quotes pending Platform review. Valid generated content is staged in a separate private result table before settlement. The subsequent save associates the draft ID atomically with the attempt and deletes the staged content. If saving fails after settlement, the teacher can recover the staged result without calling the provider again. Tenant purge removes staged content by attempt. The customer event ledger and attempt do not contain generated text.
- `aiRunLogs` now references the attempt and records measured tokens once; the old caller-supplied run-log mutations are internal. Platform sees recent token/evidence records, unsettled holds and reconciliation/overage controls. Admin sees the cycle's AI allowance and usage events. Provider OCR and unrelated paid routes remain gated. No provider price is inferred from token usage and no fictitious zero-cost provider record is written.

## Review and activation limits

Independent security and provider-evidence review is still required before a PR or deployment. The single-call design deliberately gives no automatic template/schema repair; failed validation can consume measured tokens. OpenRouter responses without trustworthy price/currency produce token evidence but no cost row. A thrown provider error without reliable token evidence remains held until an operator checks the provider records. No automated provider-report import is provided. Settlement after a crash between dispatch and result staging also requires operator evidence; retries never send the call again. A settled staged draft whose sources or template can no longer pass the existing save policy needs an operator/content decision before recovery. The recent Platform view is bounded to 100 attempts, and the unresolved view to the newest 100 across Platform.

After independent review, Platform must publish separate reviewed `teacher_lesson_plan` and `teacher_assessment` `ai_tokens` profiles matching the selected OpenRouter model IDs and worst prepared request bound, link the effective contract and start a nonoverlapping cycle with exactly one AI meter. Configure the provider key and approved model overrides only after cost review. Test a teacher quote, explicit confirmation, a measured event, failed-use settlement, reconciliation and zero-hold close in a controlled environment before enabling a school. A key alone grants no allowance; OCR stays disabled.
