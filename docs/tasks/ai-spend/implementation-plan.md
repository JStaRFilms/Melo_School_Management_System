# School AI spend activation plan

Baseline: `origin/master` at `5eaa434`. This plan covers teacher lesson-plan, student-note, assignment and assessment-draft generation only. G1 was planning; B1 now implements a single-call route. See [verification.md](./verification.md) for checks and remaining activation limits. No live provider call or deployment was part of B1.

## Decision and boundaries

Use the existing school entitlement cycle and `ai_tokens` meter, but make a confirmed quote the sole route to a provider call. Keep the paid-usage gate on provider OCR and all other paid paths. Do not wire `knowledge_upload`, `curriculum_generation` or `ai_import` to this route. Do not change payments, uploads or school storage accounting. A provider key is configuration, never authorization. Do not treat the hidden `UsagePreflight` component as approval for generation: it currently quotes only an item count, confirms a simulated reserve-and-release, and the generation buttons call actions independently.

The simplest safe route is a teacher-facing quote step that prepares the *actual* generation request, followed by confirmation that holds the school's allowance in one Convex mutation, then an authenticated generation action that claims and executes that particular attempt. The action must accept an attempt ID, not independently actionable generation arguments. Do not expose a second direct provider path. Keep the existing draft creation and template/assessment validation logic; replace only its entry and dispatch/accounting seam. Add a distinct `teacher_assessment` task profile to the existing task enum if assessments need a separately reviewed estimate, rather than quietly interpreting `teacher_lesson_plan` as all generation. Plan versions and cycle snapshots remain immutable. No generic jobs framework is needed.

Confirmation atomically writes `reserved`, `dispatch_started`, `provider_unavailable`, `released` and zeroes the hold in one transaction. `getUsageWorkspace` and `getPlatformEntitlementWorkspace` both advertise provider execution as false. `closeUsageCycle` refuses nonzero reserved units.

## Request and state contract

1. Prepare/quote: server-authenticated action validates school membership and `academic.planning.use` plus staff role, resolves the same workspace, sources, class/topic/exam scope, template and effective assessment settings as generation, builds the prompt and resolves model/provider. Validate source count, output kind, source excerpts and prompt-size ceiling *before* offering a quote. Persist a bounded attempt with school, actor token identifier, task/output, cycle, meter, selected canonical request identifiers/settings, model and prompt-policy version, immutable digest of the exact prepared request including source content and template/related artifacts, estimate, absolute expiry and idempotency key. Do not put prompt, excerpt, student data or generated text in accounting records. Treat the reviewed `unitsPerItem * itemCount` profile as a configured upper bound, not a measurement. The server must prove that the bounded prompt and all permitted calls fit that bound, or refuse the quote and require Platform to publish an adequate new plan version; never raise the estimate behind the confirmation dialog. Return estimate, `ai_tokens`, model profile and quote expiry to the teacher. A quote is not a charge. Prefer a short TTL such as 5 minutes, bounded by cycle end. Requote whenever the digest, settings, sources, template, model, plan or cycle changes. Use existing capability checks in the transactional quote/confirm functions, not only in the action. On duplicate idempotency key, compare *all* bound terms including digest; reject conflicts. Assessment settings must bind the resolved effective profile, not just the user's pre-normalized input.
2. Confirm: teacher reviews the exact output type, source count, model profile, maximum token hold and allowance impact, then supplies attempt ID, expected estimate and explicit confirmation. A single mutation checks owner identity, tenant/capability, active cycle/contract and matching meter, quote TTL, immutable digest/terms, effective allowance and current hard stop, and atomically increments `reservedUnits` and changes attempt to `reserved`. Use Convex transaction conflict retries for simultaneous teachers competing for remaining units. Existing quote/cancel behavior can be retained for other disabled tasks, but confirmation of unsupported tasks must still stop and release as before. A duplicate confirm returns the current state without another hold. Cancellation releases only an undispatched reservation or cancels a quote.
3. Dispatch: authenticated generation action receives only the attempt ID and re-prepares or loads the canonical request, verifies its digest against the quote, confirms capability and school again, checks expiry and claimed state, then atomically claims the reservation (`reserved` to `dispatch_started`) before sending anything. The client can retry *before claim* using the same attempt ID; after claim it can only read status/result. A second client/action cannot claim again. If preparation fails before claim, safely release. If the action crashes after claim, never assume the provider did not receive the request. Client/network retries must not issue another provider call. A status query reports reserved, in progress, succeeded, failed with known usage, or needs reconciliation; it must not return internal prices to school users.
4. Measure and settle: wrap each `generateObject` invocation and preserve its own returned `usage` and provider response/request ID before validation and repair; sum **every** measured input and output token count across original call, retry and repair calls, including calls whose output failed schema/business validation. For thrown errors, collect usage/response IDs only where the SDK/provider actually supplies reliable evidence. A 429 or 5xx is not automatically free and is not safe for blind replay; disable the existing automatic provider retry for the activation unless an explicit provider idempotency contract and evidence reconcile that retry. Keep bounded schema/template repair where each separate call fits the *same* confirmed aggregate budget. Put a model output-token cap on each call and a ceiling on prompt/repair input. Check remaining held budget *before* any further repair call; if insufficient, stop and settle measured work, requiring a fresh confirmed request to try again. Budget for the worst permitted sequence or reduce call count so the reviewed hold is honest. Do not infer a token count from source length for settlement. Require valid nonnegative safe-integer provider token usage; sum with overflow checks. A missing, partial or contradictory usage report, an ambiguous timeout after dispatch, or failed settlement keeps the hold in `needs_reconciliation` and blocks replay/new cycle close. Operator reviews real provider evidence before resolving; no timeout auto-release after dispatch. Keep a bounded, indexed operator view of unresolved attempts.
5. Commit measured usage exactly once, including failed generation that used tokens. Settle the attempt, meter consumption, hold release and customer `usageEvents` atomically, keyed by attempt ID; reject conflicting repeat measurements. An overestimate returns unused hold. If actual token use exceeds the hold despite configured limits, record the **full measured actual**, release the hold and visibly mark overage for Platform review; hard-stop future dispatch until reconciled. The existing generic `commitUsageQuota` refuses overages, so implement this AI-only verified branch or tighten provider calls and still provide a narrowly audited overage path. Never silently discard overage or claim zero use. Saving a draft and settlement cross transactions: idempotently save once under the attempt ID, retain result IDs, and if a save fails after known provider use settle those tokens anyway. Recover a settled-but-unsaved attempt without another provider call. No prompt or content in the cost/event ledger.
6. Provider economics are separate: use provider response ID as evidence ID only when supplied and stable, otherwise a stable attempt/call ID with explicit evidence provenance; preserve per-call model/token evidence. Invoke `recordProviderCost` only when trustworthy price and currency exist (or verified later from provider reporting), with a known conversion to minor units. Keep school token usage independent of price availability. Surface missing price/evidence to Platform, never as a fictitious zero cost. Change `aiRunLogs` to reference the attempt and report aggregate measured tokens and final state, rather than treating the final `result.usage` as all work; restrict accounting writes to server-controlled/internal mutations. A friendly action error must not erase prior evidence.

## Expiry, concurrency and operator controls

Schedule bounded cleanup for expired `quoted` and unclaimed `reserved` attempts; verify state and cycle before releasing. Dispatch claims must complete before reservation TTL and cycle end. Once a call may have reached OpenRouter, expiration only marks it for review; hold remains until measured settlement or documented operator reconciliation. An ended cycle cannot be closed while holds/uncertain outcomes remain. A later cycle must not absorb old token use. Validate that expiring grants/pools leave enough headroom at claim; settlement of a previously permitted dispatch remains tied to its original cycle. Cap concurrent in-flight holds by the actual available allowance and keep the existing school/user rate limits. An operator may resolve uncertainty only against evidence with an audited reason, never by re-running an unknown call.

## Activation checklist and stop conditions

Platform publishes a reviewed immutable entitlement version with an `ai_tokens` allowance and appropriate lesson/assessment task profiles, links a valid school contract, and starts a nonoverlapping effective usage cycle. Confirm that there is exactly one matching cycle-bound AI meter, adequate allowance and an approved model policy. Configure `OPENROUTER_API_KEY` and approved `SCHOOL_AI_*_MODEL` choices only after test and cost review. Use the active school cycle and supported AI task profile as the school-scoped activation condition; an API key by itself must not enable any path. Verify teacher quote, confirmation, successful mock usage settlement, Admin token event, Platform evidence and cycle closure with zero holds. Keep provider OCR explicitly disabled. A model with no usable token usage evidence, unbounded output, unexpected overages or an unresolved dispatched attempt blocks that school's activation or requires Platform reconciliation. No automatic billing or payment is implied.

Builder should read `packages/convex/_generated/ai/guidelines.md`, `AGENTS.md`, `packages/convex/functions/academic/usageEntitlements.ts`, `metering.ts`, `documentGeneration.ts`, the two draft save/log files and `packages/ai/src/models.ts` first. The main hazard is paying for a provider call that the last-response-only log calls free. The second is a confirmed quote for one request accidentally authorizing another. Both must have failing tests before any gate is relaxed.
