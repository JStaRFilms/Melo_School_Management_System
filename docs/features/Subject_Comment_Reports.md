# Subject comment reports

Schools can choose the reporting mode for selected classes in each academic session. The default is scores and grades. An admin selects classes at `/assessments/setup/reporting-modes` and chooses "Comments" to use subject-by-subject progress comments instead. This choice does not create students, subjects, bills, or parent accounts.

Subjects and class assignments still come from the school's normal academic setup. An assigned teacher chooses session, term, class and subject in the existing entry workspace, then writes one draft comment per student for that subject. A pupil with five subjects gets five separate comments. Admins can review the assembled student report and publish it once all applicable subjects have comments. The published report is an immutable term snapshot with the original subject names. The parent portal shows that snapshot, not teacher drafts; before publication it says the report is not ready. Grade entry and printed graded cards continue for classes in the default mode. Melo starter subject lists may be added later, but templates are not required.

For permissions, history, tenant purge and tests, see [FR-023](../issues/FR-023.md). Before release, read the [rollout gates](../tasks/orchestrator-sessions/orch-20260928-082626/release-gates.md): the graded-card class/session index is staged and cannot be queried until a later deployment after backfill. This branch fails closed on mode changes for schools with over 1,000 lifetime issued graded cards. The separate graded-parent publication change must be reconciled with `packages/convex/functions/portal.ts` before the branches are merged. Class batch printing uses issued narrative reports only and has explicit student-count and response-size limits.
