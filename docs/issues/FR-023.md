# FR-023: Subject comments for selected classes

Status: implemented in PR #89; integration and staged-index release gates remain open. FR-022 remains admissions. This issue supersedes earlier single-comment and required rubric proposals.

## Normal workflow

An admin selects one or more classes in a session and chooses the reporting mode: regular scores and grades, or comments per subject. Existing school subjects and class-subject assignments are the source of truth. Schools can name hands-on subjects like communication, potty readiness or drawing and assign them to any class, regardless of level. Melo may offer editable starter subject lists or report templates; these are conveniences, not a requirement for a school to use comment mode. Choosing a mode never enrolls students or changes billing.

Teachers use the usual session, term, class, subject and student flow. For comment-mode classes, the score cell/editor becomes a free-text comment for that student and subject in that term. Teachers save drafts. Admin reviews a clean report with one row/section per subject and explicitly publishes it. Parents see the issued report in the normal portal. This workflow is scoped by session and term; class mode is chosen per session and reports are issued per term. No numerical marks, averages, grades or ranking for comment-mode reports.

## Acceptance checks

- [x] Authorized school admin can select any one or more active classes for a chosen academic session and choose comment or graded reporting. Default is graded, independent of class level. A new session has its own choice. Switching after any graded or comment report has been issued for that class/session is blocked. Enrollment, billing and portal credentials do not change.
- [x] Admin can use the existing subject management and class-subject assignment flow for comment-mode classes. Comment-mode subjects come from the class's assigned subjects or that student's explicit session selections if present. Unlike graded totals, a calculated aggregation umbrella does not require a separate teacher comment; teachers comment on its manually entered component subjects. Subject lists are editable by the school; optional Melo-provided starters do not hard-code preschool labels or replace existing assignments. A comment report cannot be published with no applicable subjects, but the school can add/assign subjects through normal setup.
- [x] An authorized teacher assigned to the class/subject and school admin can enter, edit and save a free-text draft comment for each applicable student, subject, session and term. Student/subject membership, session/term, tenant and teacher assignment are checked server-side. Unrelated teachers, parents and schools cannot read or change drafts. In comment mode, score entry and grading endpoints cannot silently create formal marks for those subjects.
- [x] Admin can preview and publish one student's report when every applicable subject has a meaningful comment. A stale preview cannot publish. Duplicate publish is idempotent; the immutable snapshot contains subject IDs/names/order and comments, student/class/session/term context and issue actor/time. Later subject renames, assignment changes, promotion and theme changes do not change an issued report. Issued comments cannot silently change. Graded and comment issuance are mutually exclusive for the same student/term.
- [ ] Parent/student reads expose comment-mode reports only after publication for their own linked student. An unissued comment report yields only a neutral not-ready state, no draft, score fallback, partial comments or draft-derived notification. Selected view, dashboard, results, history, notifications and print enforce the same server-side guard. Existing graded parent publication policy remains owned by a separate agent; integrate changes without undoing either policy.
- [x] Admin and teacher use normal session/term/class/student selectors and per-subject entry. The report card shows tidy subject names and comments, student/class/term context and branding. No score, grade, average, rank, pending-score or cumulative-warning UI for comment-mode reports. Staff draft print says "Draft, not published"; parent print uses issued snapshots. White paper and readable monochrome output; tenant branding follows `@school/shared/theme`.
- [x] Tests cover default graded, class/session scope, same-school subjects, explicit student selections, subject/class teacher authorization, score-entry guard, multiple students and subjects, stale review, missing comments, duplicate publish, immutable history, cross-tenant/guardian access, portal draft gating, print and existing graded regressions. Run focused tests, typecheck, lint/build where feasible and `node scripts/audit-theme-colors.mjs` for touched school-facing files.
