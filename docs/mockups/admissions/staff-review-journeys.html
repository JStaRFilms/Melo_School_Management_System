07 · Staff recovery & error state gallery Every operation has a visible safe recovery action

Recovery states

No matching applications

Adjust or clear bounded filters. Do not turn an empty result into a cross-tenant existence signal.

Not found or denied (`NOT_FOUND_OR_DENIED`)

Return to queue/check school context; do not state whether the record exists.

Payment pending

No manual slot grant; use evidence/reconciliation workflow.

Application incomplete

Request changes or complete permitted review work; do not decide around missing requirements.

Transition unavailable

Refresh current state, then use an allowed action. Staff never override state directly from UI.

Sensitive access unavailable

Escalate/request correct grant (`applications.view_sensitive`); no preview or filename disclosure.

Conversion running

Refresh ledger status; do not start another conversion.

Onboarding pending (`ONBOARDING_PENDING`)

Monitor/retry communication outbox; conversion remains complete.

Session confirmation needed

Fresh re-auth returns to document/decision/conversion context after success.

Responsive / accessibility note On mobile, filters open in an Apply/Clear drawer, the queue becomes labelled cards or an announced scroll region, and detail rail stacks above tabs. All status colors pair with text, dialogs retain focus, live updates use polite live regions, and destructive actions require deliberate confirmation.
