07 · Staff state and empty/error galleryEvery operation has a visible safe recovery

Recovery states

No matching applications

Adjust or clear bounded filters. Do not turn an empty result into a cross-tenant existence signal.

Not found or denied

Return to queue/check school context; do not state whether the record exists.

Payment pending

No manual slot grant; use evidence/reconciliation workflow.

Application incomplete

Request changes or complete permitted review work; do not decide around missing requirements.

Transition unavailable

Refresh current state, then use an allowed action. Staff never override a state from UI.

Sensitive access unavailable

Escalate/request correct grant; no preview or filename disclosure.

Conversion in progress

Refresh ledger; do not run again.

Onboarding pending

Monitor/retry communication outbox; conversion remains complete.

Session confirmation needed

Fresh re-auth returns to document/decision/conversion context after success.

Responsive/accessibility noteOn mobile, filters become an Apply/Clear drawer, the queue becomes labelled cards or an announced scroll region, and detail rail stacks above tabs. All status color has text, dialogs retain focus, live updates are announced, and destructive actions require deliberate confirmation.
