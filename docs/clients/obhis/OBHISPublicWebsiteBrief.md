## 1. Purpose and Audience

Create a credible, warm, bespoke public website for Olive Blessed Crest Academy that helps families understand the school, assess fit, plan a visit, and enter the separate online admissions experience. The website should feel designed for this school rather than selected from the existing `apps/sites` template catalogue.

Primary audiences:

- parents/guardians considering early-years, primary, or secondary entry
- current families looking for contact, visit, programme, or policy information
- prospective staff/community members as a secondary audience

Primary user outcomes:

1. Understand what age/stage programmes the school currently offers.
2. Understand the school’s approved values, approach, and learning environment.
3. See authentic, rights-cleared evidence of facilities and school life.
4. Contact or visit the school using current confirmed details.
5. Start an application through the canonical admissions surface.
6. Reach the portal only if OBHIS approves a current-family link.

Navigation recommendation:

```text
Home | About | Programmes | Admissions | School Life | Visit/Contact | [Apply]
```

On mobile, “Apply” remains visually distinct but not sticky in a way that blocks content or accessibility. A current-family portal link belongs in utility navigation/footer only if approved; it should not compete with prospective-family admissions.

### Page/funnel flow

```text
Search/social/referral
  -> Home or Programme page
  -> evidence: approach + programmes + authentic environment
  -> Admissions overview or Visit
  -> canonical application URL on product-owned admissions surface

Current family
  -> Contact/footer utility
  -> canonical portal entry (only if enabled)
```

The managed site’s `/apply` is a no-index `307` convenience redirect. It must not render, proxy, iframe, or duplicate the application flow.

## 7. Bespoke Visual Direction for D2

### 7.1 Design character

Recommended direction: **“rooted growth, confident care.”** Build a contemporary Abuja school presence with human warmth and clear academic progression. Draw cautiously from the source’s green identity and “Integrity & Service,” but do not reproduce the dated brochure layout, generic child cut-outs, or template-era institutional cards.

Design principles:

- **School-first:** no Melo/platform marketing in the public experience unless explicitly approved.
- **Evidence over superlatives:** current programmes, actual spaces, named processes, and authentic voices instead of “expert,” “best,” or “world-class.”
- **Progression:** visually connect early years, primary, and secondary without making unapproved continuity claims.
- **Care without medical overclaim:** show calm routines and safeguarding signals only through approved specifics.
- **Bespoke composition:** an OBHIS route/component system, not `classic-institutional` with different colors.

### 7.2 Preliminary token direction (not approved brand values)

D2 should derive final values from an original logo file and contrast testing. Working exploration only:

- deep evergreen for authority and continuity
- brighter leaf green used selectively for growth/action
- warm clay/gold accent acknowledging the cap/book detail in the source logo
- warm off-white and ink neutrals for legibility
- avoid large pale-green text fields and red/green reliance from the brochure

Typography should be readable, modern, and locally performant. Use at most two font families, with a strong sans-serif body and an optional restrained editorial display face. The old script typography is not suitable for long digital headings.

### 7.3 Photography treatment

Use full-resolution, naturally lit, current photography with consistent color treatment. Prefer environment, learning interaction, materials, hands, and consented group activity over isolated stock portraits. Do not digitally extract or upscale the brochure’s embedded children. Avoid showing names, assessment sheets, medical information, or identifiable records.

Missing imagery should produce a deliberate typographic/illustrative composition, not stock children or grey “coming soon” boxes.

## 11. Accessibility Requirements

D2/B5 acceptance baseline:

- WCAG 2.2 AA target.
- Semantic landmarks, one logical H1, ordered headings, skip link, descriptive page titles.
- Full keyboard operation, visible focus, no keyboard traps, and 44-by-44 CSS-pixel target guidance for primary controls.
- Text/background contrast at least 4.5:1 for normal text and 3:1 for large text/UI components; do not rely on red/green alone.
- Responsive reflow at 320 CSS pixels and up with no two-dimensional scrolling for normal content.
- Navigation state and mobile menu announced correctly; focus managed on open/close.
- Meaningful alt text tied to page purpose; decorative images use empty alt; galleries do not repeat captions as alt text.
- Captions/transcripts for time-based media; no autoplay audio/video.
- Reduced-motion support and no essential parallax/rapid motion.
- Plain-language forms/links; application opens as a clearly named destination, with cross-origin behavior communicated where helpful.
- Map/contact information also available as text; no map-only directions.

## 12. SEO, Privacy, Analytics, and Performance

### SEO

- One canonical HTTPS managed domain only after verified routing/TLS/cutover approval.
- Preview and noncanonical/inactive hosts are no-index; aliases 308 to canonical preserving paths.
- Unique approved title/description per published route.
- School/EducationalOrganization JSON-LD includes only approved name, postal address, phone, email, logo, URL and programme statements.
- Current approved OG image; no brochure photo fallback.
- Sitemap includes only published routes and uses actual publication/update timestamps.
- Redirect map is required if replacing an existing OBHIS site; do not redirect every missing URL to home.

### Privacy/analytics

- Publish a current privacy notice/contact before collecting analytics requiring it.
- Use only the shared code-owned analytics adapter; no pasted scripts.
- Events may record page/CTA/source but no child, guardian, contact, application, health, or document data.
- Never expose application documents or uploaded applicant photographs as website assets.
- Contact links should not promise response times unless operationally approved.

### Performance budget

Test on representative mid-tier mobile/4G and production-like hosting:

- p75 Core Web Vitals target: LCP <= 2.5 s, INP <= 200 ms, CLS <= 0.1.
- Lighthouse mobile targets on key routes: performance >= 90, accessibility >= 95, best practices >= 90, SEO >= 95 (investigate and document unavoidable deviations).
- Above-fold hero image target <= 250 KB in an appropriate AVIF/WebP derivative; responsive `srcset`/sizes required.
- Initial page image transfer target <= 1 MB; lazy-load below-fold galleries.
- No autoplay video; poster and explicit play if video is later approved.
- At most two font families and minimal required weights; self-host/subset where licensing permits; avoid render-blocking third-party font CSS.
- Reserve image/media dimensions to prevent layout shift.
- Keep client-side JavaScript limited to interactive navigation/analytics; static content remains server-rendered.
- Third-party map/chat/social embeds load on user action or after consent, not in the critical path.
